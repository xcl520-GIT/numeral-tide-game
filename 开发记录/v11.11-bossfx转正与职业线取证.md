## 一、A · bossfx 转正：它压着的是一个"不属于它"的 bug

`bossfx`（Boss 行为差异化）功能在 v11.5 P4 就完工并验收过，但一直**默认关**。
压着它的是一句话：**bossfx=1 跑 2700 局会出现 1 例 stall / timeout，bossfx=0 是 0 例。**
那一轮判定"它与 P4 无关，是无头 AI 自己的盲点，属于下一轮单独做的一件事"。

本轮把那件事做完了。**根因四处，没有一处是 bossfx 的 bug —— 它只提高了撞见率。**

### ① A* 步数上限（28.4% 的"走不到"只是"搜不到"）

`_walkToward` 调 `findPath(..., 4000)`，4000 是 A* 的**展开步数**上限。实测 900 局里它失败
268 次，**全部**都是"目标格自身可走"（不是目标非法）。把上限抬到 20000 有 76 次（**28.4%**）
能找到路；再抬到 60000 **一次都不增加** ⇒ 20000 就是够的那个数。→ 抬到 20000。
（剩下 71.6% 是**真不连通**：距离只有 6~18 格却三种上限都搜不到 —— 那是地图生成的事。）

### ② "站在目标格上"的出口：既不记账也不离开

渊喉的吼是**直接改 `px/py`** 的（不经过 `_enterTile`），所以把玩家搬到宝箱格上时
**格子不会被消耗**；而 `_nearestTile` 会返回"距离 0"的它 → 每轮重选 → 每轮走到这个出口 →
**原地空转 40 次 = stall**（`playHeadless` 的判据正是"连续 40 次 false"）。
→ 改成"（非 exit 时）拉黑它 + 走一步离开"。

⚠ 这里踩过一个坑并留了记号：**exit 绝不能拉黑**。第一版把它一起拉黑了，结果
"1 例 stall"当场变成"**12 例 timeout**" —— exit 是唯一出路，进了黑名单就再没人选它。

### ③ 门锁着时还把 exit 当目标

门锁的条件就是"本层 Boss 还活着"（`_enterTile` 里那句"潮汐之门被封锁着 —— 先解决这层的守卫"），
所以这时走 exit 只能站在门上干等。→ 门锁着就直接把 Boss 当目标。

### ④ `_pickTarget` 会主动排除 Boss

它的评分里有 `if (cost / st.hp > 0.45) sc -= 90;`（"打起来太亏就绕开"）。
而门锁着时 **Boss 不是"可打可不打的敌人"，它是门的唯一钥匙** ——
于是 AI 一路绕开 Boss 刷杂兵、永远开不了门。那一例 timeout 的现场正是
`kills=751`、`bossAlive=true`、门在 3 格外。
→ 门锁着时**直接锁定 Boss**，不经 `_pickTarget`、也**不看黑名单**
（地形会变，一次走不到就永久放弃它等于把这一层判成死局）。
并在 `_autoStep` 末尾加兜底：连"唯一出路"（exit / Boss）都走不到时**消耗一回合**，
而不是空转 —— 空转会把整局判成 stall 并作废，而等待让潮水涨退改变水路代价。

### 验收与记账

| | 休闲 | 标准 | 深渊 |
| :--- | :--- | :--- | :--- |
| bossfx=1（2700 局） | dead254/win646 | dead522/win378 | dead723/win177 |
| bossfx=0（2700 局） | dead252/win648 | dead520/win380 | dead719/win181 |

**三档全部 0 stall / 0 timeout**（开或关都是）。冒烟 291 ALL PASS（第 52 节的断言用显式传参，
所以默认值变更不会误伤它 —— 这一点是 v11.10 那次 `deepCorrupt` 教训换来的）。
Boss 行为确实在跑：潮汐节拍 608/455/578 次、督军召出 158/87/53 只、渊喉吼 149/104/55 次。

⚠ **本轮重标了 AI 基线**（v11.5 P4 早就警告过"改 `_autoStep` 会让三档不可比"）：

## 二、B · waitcost 转正：一条"只对真人生效"的规则

`core.js` 的 `waitCost` 默认 `'0'` → `'b'`；`sim.html` 同步。
（游戏本体 `main.js` **不传**这个参数，走的正是这个默认值 ⇒ 转正即对玩家生效。）

**选 b（累积惊动）不选 a（额外推进潮汐节拍）**：a 直接改写节拍表；b 只借用
"已醒的敌人"这条现成路径，半径复用 `PACK.alertR`（"它察觉得到你"的距离，全游戏只该有一个）。

⚠ **记账方式必须写清，否则一定会被误读成"改了没用"**：
这条代价对**模拟基线逐位无影响**，而且那是**预期** ——
无头 AI 从不等待（v11.5 两次给它造动机都被数据否掉），所以它在模拟器里**永远不被触发**。

**验收因此不是"数字变了"，而是"数字逐位不变"**：三档 71.0 / 42.7 / 21.7 与转正前**逐位相同**
（turns / kills / relics / 结束层分布 / 常驻指标行全同；等待占比 0%）。冒烟 291 ALL PASS。

## 三、C · 职业线：为什么判定"不调"（本轮最有价值的取证）

### 第三发 AI 等待策略：是"没收益"还是"门槛太高"

v11.5 说"AI 没有值得等的东西"，而那句话被 v11.6 引用来**冻结整条职业线**
（"P0 量的是不能刷回合的前提下谁强，真人会刷，排序未必迁移"）。
但这两件事没被分辨开：是**等待真没收益**，还是 **`_aiShouldWait` 门槛太高**（它要求
身边一格无敌人 + **残血 <55%** + 目标 ≤4 格 + 冷却差 1~3 回合 + 连续等待 ≤3 次）？

把门槛一层层拆开（`probe_aiwait3.html`，n=300/档）：

| 配置 | 等待占比 | 等待/局 | 休闲 | 标准 | 深渊 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 原判据 + 免费等待 | 0.2~0.5% | 0.6~1.3 | 72.7% | 43.0% | 24.3% |
| 放宽连续/冷却 | 0.7~1.3% | 2.0~3.3 | 72.0% | 42.7% | 25.7% |
| **再去掉残血限制** | **2.8~3.6%** | 8.3~9.6 | 72.3% | 44.3% | 25.3% |
| 同上 + **有代价(waitcost=b)** | 同上 | 同上 | **一模一样** | **一模一样** | **一模一样** |

**等待占比涨了 6 倍，通关率纹丝不动（≤1.3pp）** ⇒ **「等」本身没有收益**（是"无收益"，不是"门槛高"）。
两个附带结论：**职业线解冻**（"真人会刷所以矩阵不可信"这个顾虑不成立）；
`waitcost=b` 对 AI 无影响（也再次印证 B 的记账）。

### ★ 但玩家感知与数据**完全相反**

| | 玩家原话 | 数据 |
| :--- | :--- | :--- |
| 疾风（ranger） | "疾风更是牢中之牢"、"技能约等于没有" | **第二强 62%** |
| 法师（arcanist） | "法师断档的强"、"远程来回刷回合就能轻松无伤" | **最弱之一 17.3%** |

两条根因都能说清：

1. **模拟 AI 只会贴脸打，不会风筝。** `arcanist` 的"远程刷回合"优势在模拟里根本发挥不出来；
   而 `ranger` 的 `spd 26` 在 v11.7 量过的"速度碾压"机制里是**硬收益**
   （对杂兵 spd 4~16，每轮多打一次）。**同一条机制，真人感知不到、模拟器却按满额计。**
2. **`ranger` 的被动玩家感受不到。** "每场第一轮先攻 +40%" 在接触结算里只值第一轮 ——
   v11.5 P0 当初就猜到了这一点，玩家原话"技能约等于没有"正好印证。

⇒ **判定：职业数值不按这份数据调**（方向可能是反的），本轮不动刀。
→ 但"疾风的被动没有存在感"是一条**独立、可验证、可落实**的改进（v11.5 留了两个候选：
a 先攻附带本轮可脱离一格 / b 第一轮命中后本场每轮多打 1 次），列进下一步。

## 四、这一步之后，职业线上真正该做的两件（下一步）

1. **让 `ranger` 的被动有存在感**（v11.5 的候选 a / b 二选一，跑前写死判据再拍）。
   ⚠ 它同时会**加强** `ranger`（已经 62%），所以必须和"基础速度要不要回收一点"一起看 ——
   否则会把 52.6pp 的极差继续拉大。
2. **给模拟器补上"风筝"这个策略**，否则远程职业（`arcanist`）在模拟里永远是弱的，
   而职业平衡**只能靠这份数据判**。这是 C 真正被卡住的地方 ——
   不是"职业无法平衡"，是"**量具量不到玩家实际在做的那件事**"。
   （对照 v11.8 的教训："它是不是也是资源"；v11.9 的"分子还是分母"；
   v11.10 的"这条链上的对手在哪" —— 这一条是第四问：**"量具量得到玩家在做的那件事吗？"**）

## 六、本项新增的坑（已并入 README 的「工程坑」一节）

1. **普通 `function(){}` 里的 `this` 不是 Game。** 一次 `Object.keys(this.aiBad).forEach(function(k){…})`
   直接让 sim 全线 SIMFAIL（`Cannot read properties of undefined`）。
   要改对象就"先收集再删"，别用 forEach 里的 `this`。
2. **`sim.html` 的 `cls=0` 是"关掉分职业"**，不是"跑全职业"。想拿矩阵要**不传 cls**。
3. **探针跑太久会丢 stdout**（这次 `-dumpRaw` 的输出是 0 字节，但 `-out` 的文件是好的）。
   取数时先看文件大小，别只看 stdout。
