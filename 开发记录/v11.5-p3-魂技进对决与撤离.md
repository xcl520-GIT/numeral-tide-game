## 一、做了什么

### 第二步 · 魂技进对决（`0948ad1` / `99702fb`）

**引擎**：给一场对决开一个「本轮效果槽」。

| 钩子 | 位置 | 语义 |
| :--- | :--- | :--- |
| `duel.armRound(fx)` | core 的 newDuel | 给**下一轮**挂一份效果；已在槽里就返回 false |
| `duel.pendingFx` | 同上 | 界面据此把按钮标成"已挂" |
| `strike(src, dst, atkType, **fx**)` | 同上 | fx 是**参数**不是闭包量 → "只作用在指定那一轮"是结构性的 |
| `Game.duelUseSkill(duel)` | core | 规则唯一归属地：每场一次 + 扣冷却 + 挂哪一轮 |

四条效果走的是**和遗物 flags 同一套乘法系数通道**（`data.js` 的 `DUEL_SKILL` 一张表）：

| 技能 | 效果 | 实现要点 |
| :--- | :--- | :--- |
| 裂地斩 `quake` | 伤害 ×1.6、承伤 ×0.5 | 承伤那一步必须记下**减免前**的 `preMit`（反伤要用它） |
| 潮语洪流 `torrent` | 无视姿态，按弱化侧结算 | 回到原始 `st` + `bestAttack` 选路；**不拿克制奖励**（技能替玩家读了面板，奖励发的是"你读对了"） |
| 疾影 `blitz` | 本回合额外一次出手 | 主击打死目标就**换一个活着的**继续打；不对尸体补刀 |
| 不退之壁 `bulwark` | 本轮免伤 + 反伤 40% | 免伤要能真到 0 —— `Math.max(1, …)` 会把它抬回 1 点血，文案当场变谎话 |

**界面**：`ACTS` 注册表支持函数标签与"已挂"状态，魂技是第 4 个动作（键 **3**）。
按下去**只挂算式、不占回合**，打哪一路仍由玩家选 —— 技能不该替他把"打硬化面还是弱化面"这道题做掉。

### 第三步 · 撤离（engine + ui + 量具，见 git log）

三条**从代码里读出来的**前提，让它比想象中简单得多（值得记下来）：

1. `stepTo(x,y)` 撞上敌人时**不把玩家挪到敌人格上**，只 `_fightBegin` + `liveFight`。
   → 「撤到哪一格」这道题不存在，**不需要任何新的位置状态**。
2. 敌人血量写回模型只有 `_fightSettle` 一处。
   → 「保留残血、再进战从当前血继续」**自动成立**，一个字都不用写。
3. 潮汐"推一节拍"有现成函数（P1 为"等待的代价 a"抽出来的 `_tideAdvance`）。
   → 复用同一份周期代码。

定价三件套落在 `data.js` 的 `FLEE` 一处：`lootMul 0.5` / `tideBeat 1` / `aiDmgFrac 0.30`。
菜单第 5 个动作「撤离」（键 **4**），顺序按**破坏性**排：打 → 挂算式 → 退出。

## 二、四格归因矩阵（n=300×3，同一把尺子）

P3 第二步默认是"两件事一起开"，实测第一版把两件事混在一笔账里了，拆开重跑：

| duelskill / duelcd | 休闲 | 标准 | 深渊 | 对决魂技 |
| :--- | ---: | ---: | ---: | ---: |
| 0 / 0（旧基线） | 66.7 | 35.7 | 28.0 | 0 |
| **0 / 1（只开冷却口径）** | 68.3 | 42.3 | 32.3 | 0 |
| **1 / 0（只开新入口，含 AI 留手）** | 60.3 | 31.3 | 18.3 | ~1300/档 |
| 1 / 1（两个都开，含留手） | 67.0 | 34.7 | 26.7 | ~2900/档 |

两条结论各自成立（n=300 的标准差约 2.8pp）：

1. **冷却随战斗轮走 = 一次难度下调**：+1.6 / +6.6 / +4.3pp。
   量级不小 —— 战斗很频繁（约 30 场 × 2.5 轮），每局等于多走 75 格冷却，差不多把冷却减半。
   口径上它是对的（一轮 = 一个世界回合，和 `_fightRoundTick` 里敌人的行动时钟同理），
   但"口径对不对"和"要不要现在改难度"是两件事 → **默认收回 0**，开关留着。
2. **AI 贴身留手 = 有害**：−6.4 / −4.4 / −9.7pp。
   原因很具体：地图上的裂地斩同时给了"掀开一格 + 撞墙震晕 + 不吃反击"，
   **那是一次免战**；把它收起来留给对决，AI 就再也逃不掉，于是死得更多。
   → **默认 0**（旧行为），开关留着 —— 它回答的是"两个入口抢同一份冷却时谁更值"，
   眼下的答案是**地图那一侧赢**。要反转得先把对决侧的价值做大，不是靠改 AI 偏好硬拗。

### 默认档（`duelskill=1, duelcd=0, duelai=0`）

**64.3 / 33.3 / 27.0**，`对决魂技 542 / 524 / 978 次`（≈1.8~3.3 次/局）。

对基线 66.7/35.7/28.0 是 −2.4 / −2.4 / −1.0pp —— **在噪声带内**（σ≈2.8pp）。
新入口是"顺其自然"地用（地图入口的触发更早，所以机会不多），
这笔小账来自"这份冷却花在对决里而不是地图上"。

## 三、一个必须交代的负面发现：撤离现在是**严格劣势**的选项

| 配置 | 休闲 | 标准 | 深渊 | 撤离次数 | 每局击杀 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 默认（仅玩家入口） | 64.3 | 33.3 | 27.0 | **0** | 24.9 |
| `?fleeai=1`（**没有**脱接触） | 38.3 | 16.3 | 12.3 | 832~1421 | **14.6** |
| `?fleeai=1`（补上脱接触之后） | 44.7 | 18.3 | 13.3 | 1369~6650 | 16.0 |

**−26.0 / −17.0 / −14.7pp**，远超噪声带。根因不是判据写错，是**这个游戏里撤离换不到安全**：

> 战斗是从「相邻」开始的（`stepTo` 遇到敌人只开一场对决，玩家没挪过位置）。
> 撤完之后敌人还在**旁边**、还醒着 —— 它下一回合照样打你。
> 于是撤离目前只等于「放弃这一场的收益 + 把潮水推一节拍」，**没有换来任何东西**。

工作单给撤离定了**代价**（掉落减半 + 水位推进 + 保留残血），但没定**它买到什么**。
这一条要用数据说话，数据说：对 AI 而言它是纯亏，而且亏得很大。

### 已补：脱接触（用户拍板，2026-09-24）

组合的两下（都收在 `core.js` 的 `duelFlee` 里）：

| 补了什么 | 怎么实现的 | 为什么这么实现 |
| :--- | :--- | :--- |
| 把玩家**推开一格** | `_pushBackFrom(foe, 1)`：沿"远离那只敌人"的主轴推，撞墙或被占就停（返回**实际**格数） | 与 `_knockback` 是镜像。**尽力而为**：撤离的收益不该因为"身后正好是墙"变成负的 —— 那只是这一格不存在 |
| 被你甩开的那只**这一回合不追** | `foe.fleeGrace = true`，在 `endTurn` 里一次性消费 | 不复用 `stun`：眩晕会挂出"被震晕"的徽章与飘字，而玩家并没有震晕它 —— **界面替机制撒谎是最难查的一种**（徽章显示正确，错的只是原因） |

**顺序不能反**：先推再挂 grace。反了的话"它这一回合不追"会花在那一格还贴着你的
敌人身上，玩家看不出任何区别（它本来就能打到你）。

**效果**：`fleeai=1` 从 −26.0 / −17.0 / −14.7 改善到 **−19.6 / −15.0 / −13.7pp**
（脱接触本身值 +6.4 / +2.0 / +1.0pp）。

**但仍然很差，而且原因变了**：不是"换不到东西"了，而是**AI 判据太灵敏** ——
`撤离 1369~6650 次`（≈22 次/局 ≈ 逢战必撤），于是收益全丢、也升不了级
（每局击杀 24.9 → 16.0）。判据原文是"预期本轮承伤 > 剩余血 30%"，
而群战里它是**把所有活着的敌人的最强攻击加起来** —— 4 只 × 15 点轻松超过
剩余血量的 30%。所以 `fleeai` 保持默认关、不进基线；
**重定判据（或者干脆让 AI 不主动撤）是下一个话题的活**。

玩家入口本身是**平衡中性**的（默认档与 P3-2 默认逐位相同，`撤离 0 次`），所以留着。

## 五、这一轮逮到的四个真缺陷（都不是断言写错）

1. **追打会凭空蒸发**：主击杀掉目标时额外那一击没地方落
   （探针实测：疾风第 1 击 59 点直接收掉祷者）→ 改成换一个活着的目标。
2. **`duelUseSkill` 只认 `liveFight`** → 无头路径恒 `nofight`。
   而它的表现不是报错，是"AI 一整局一次都不放"（n=900 里 `对决魂技 0 次`）。
   根因是无头路径**刻意不把句柄挂在实例上**（隐藏类迁移，整局慢 3 倍），
   句柄只活在 `fight()` 的局部 → 规则改成认**显式句柄**，缺省才回落。
   ⚠ 这一条只有既有的第 50 节那条断言逮得住，新加的九条全绿着。
3. **P3 第二步第一版把两件事记成了一笔账**（冷却口径 + 新入口）→ 拆成两个开关重跑。
4. **断言写反**（"留手"那条等的是"放了"）—— 自己写错的，记在这里免得下次再犯。

## 六、悬而未决

1. **撤离的 AI 判据要重定**（见第三节）：30% 阈值 + 群战累加所有敌人 = 22 次/局。
   在它修好之前 `fleeai` 不进基线（默认 0）。玩家入口与脱接触都已就位、已验证。
2. **冷却口径要不要转正**（+1.6/+6.6/+4.3pp 的难度下调）。这是设计决定，不该由实现顺手定。
3. `duelai`（AI 留手）在被证伪后仍留着开关：它是"两个入口谁更值"的唯一量具。
   如果以后把对决侧的技能做强到值得留手，这个开关就是现成的验证入口。
4. ~~菜单从 3 个按钮变成 5 个 —— 还没看截图~~ **已解决，而且比截图更硬**：
   在冒烟里量 `scrollWidth vs clientWidth`（第 53 节），
   `5 个按钮的入参都在框内（5 个按钮之后没有溢出）`。
   溢出不报错、不撑开布局，只让字跑到框外 —— 人工看截图会漏，常驻断言不会。
   （`probe_shot` 的 `battle` / `duel` 两个模式都不露指令菜单：前者走自动打完、
   后者没走到战斗态，所以那两条路取证不成 —— 这也是选"量在冒烟里"的原因。）
