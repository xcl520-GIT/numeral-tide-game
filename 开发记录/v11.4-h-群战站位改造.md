# v11.4-h · 群战站位改造（2026-09-24）

> 上一轮（v11.4-g）三条机制全部无效、整批回退。这一轮**先归因、再动手**，
> 并按外部参考（`v11.4-g-求助单回答-群战站位.md`）指出的顺序做：
> **先分格，再加速**。
>
> 结果：群战占比 **6% → 15~16%**（提高约 2.6 倍），四邻 1.04 → 1.17。
> **目标（1v1 占比 < 60%，即群战 ≥ 40%）仍未达成**，但每一格提升都有归因。

## 一、先归因，再动手（这一步是上一轮缺的）

新增 `tools/probe_approach.html`：包一层 `endTurn`，对**每一次敌人行动**逐一判定
"这一回合它到底发生了什么"。标准难度 n=30（9.7k 回合 / 17.7k 次判定）：

| 它在干嘛 | 占比 | 读法 |
|---|---|---|
| 等到自己回合（每 2 回合一步的节奏） | 36.9% | 一半行动被自己的时钟吃掉 |
| **走了** | 47.5% | 但只有 **9.1%** 落在玩家四邻 |
| 走不动：被同类挡住 | 8.4% | |
| 邻身出手（距离 ≤1） | 3.7% | 玩家通常是**主动**走过去打 |
| 走不动：寻路失败 / 目标是玩家格 | 0% | 这两个假设**排掉** |

**接战那一刻，玩家四邻只有 1 只怪的概率是 93%。**

然后加了外部参考建议的两列打点，把假设判掉：

| 打点 | 实测 | 结论 |
|---|---|---|
| 目标格冲突率（几步内想走同一格） | **1.7%** | **"同侧排队堵门口"假说被否掉** |
| 想动的怪 / 回合 | **1.02 ~ 1.68** | ✅ **真正的瓶颈：玩家所在房间里本来就只有 2 只怪** |
| 冻结税（一场仗 R 轮只推进 1 个世界回合） | 占整局 **9.2~10%** | 真的存在，且是 A1 拉长战斗之后才出现的 |

`packcheck.html` 再补一刀：开局 87% 的怪在距离 ≤2 内有 2~3 个同伴 ——
**堆是存在的，是进房之后"不够用"。**

一句话：**四邻要站满，得先"有"第四只。** 上一轮三条机制（更快 / 成群 / 每轮推进）
全部无功而返，根因就在这里。

## 二、改了什么（五处，全部带开关）

顺序就是外部参考给的顺序 —— **先分格，再加速**。

| # | 改动 | 开关 | 为什么 |
|---|---|---|---|
| 1 | **一堆 = 一个房间**：敌人按区域成堆布点，堆内只走正交邻格、不许跨区 | — | 跨区的堆会被区域门禁关在门外，"一间房四只"缩水成两只 |
| 2 | **每堆 3~5 只、只占一部分房间**（其余空着） | — | 第一版"每间房都放"实测只放得下 2 只；空房间同时是节奏里的呼吸点 |
| 3 | **槽位指派**：把玩家四邻的格**分配给不同的怪**，每只怪寻路到自己的槽位 | `?slots=0` | 各自寻路到玩家的必然均衡就是"从同一个方向来"（参考：L4D attack slots / 阿卡姆令牌 / Unity Surround AI） |
| 4 | **槽位粘性**：已经拿到槽位且离它 ≤3 的续用 | — | 不这么做会"抢椅子"：玩家每挪一格就重分，两只怪来回换槽位、谁都走不到 |
| 5 | **战斗中的世界时钟**：一场仗的每**一轮**推进一次敌人时钟 | `?tick=0` | 治冻结税。这不是"让敌人变快" —— 它们整场能挪的次数仍是 轮数/2 |
| 6 | **被惊动的房间每回合都挪** | `?alert=0` | 参考里的"再加速"。**必须排在分格之后** —— v11.4-g 证明分格没做时加速只是更快地排进同一条队 |

第 6 条的效果也印证了这个顺序：单独加它（v11.4-g）四邻 1.04 → 1.05；
放在分格之后再加，四邻 1.16 → 1.17（本就已被前三件套抬上来了）。

## 三、每一格的归因

| 版本 | 群战占比（休闲/标准/深渊） | 开战四邻 | 说明 |
|---|---|---|---|
| v11.4-f（起点） | 6% / 6% / 10% | 1.04 / 1.05 / 1.08 | |
| + 每间房一堆（2 只） | 5% | ~1.00 | 反而更差：房间被切成更多小块 |
| + 槽位 + 世界时钟 | 9% / 10% / 16% | 1.10 / 1.11 / 1.18 | **主要来源** |
| + 大堆（3~5 只）+ 空房间 | 17% / 15% / 16% | 1.18 / 1.17 / 1.19 | 第二个来源 |
| + 惊动加速 | 14% / 15% / 15% | 1.16 / 1.17 / 1.17 | 噪声内，不亏 |
| + 槽位粘性 | **15% / 15% / 16%** | 1.17 / 1.17 / 1.18 | 微涨 |

顺带一个反常但真实的现象："距离 2 以内"的怪从 0.74 **降到** 0.62 ——
因为槽位把怪拉到了四邻（距离 1），不再堆在距离 2 观望。这是变好的信号。

## 五、还没做到的，以及下一根杠杆在哪

目标 ≥40%，现在 15~16%。剩下的墙是**时间**：

> 玩家是主动方（1 格/回合，且何时接战由他决定）。
> 他在"最近那只刚贴上"的那一刻就踩上去 —— 而其余几只还在路上。
> 槽位让它们**最终**会围住他，但围住的时候，第一只已经死了。

**下一根杠杆（建议，不要把力气花在"再快一点"上）**：

**惊动半径要独立于区域门禁。** 现在怪只在"玩家已经踏进这个房间"之后才开始行动，
也就是它们比玩家晚出发整整一个房间的距离。等玩家走到第一只面前，其余的
才刚迈出第一步。若把惊动改成"玩家进入 7~8 格范围就开始收网"，
整堆会**同时**朝他移动（速度相同 ⇒ 同批到达），这才是"一起扑上来"。

代价是"怪会离开自己的房间"，与"怪关在各自房间"的字面有冲突 ——
所以它需要和"守位"配对：**平时守在房间里，被惊动后允许出击，
脱战或玩家离开房间后回到守位**。这是参考单第 2.1 节的"守位 + 联动惊动"，
我这一轮只做了后半句。

另外，"1v4 会不会把通关率打穿"这个担心，参考单给的解法是
**占位与出手分开**（围满 4 格、但每轮只有 K 只有出手权）——
这一轮还没做，等群战占比真的上去之后再上，否则现在是空转。
