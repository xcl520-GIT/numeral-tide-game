## 四、这份代价的账（本轮的核心产出）

跑 `roadw=2&squad=0`（关掉群战，只留"走廊变宽"一个变量）拆出来的：

| | 纯地图效应 | 群战率那一份 | 合计 |
| :--- | ---: | ---: | ---: |
| 休闲 | +0.3 | −3.3 | −3.0 |
| 标准 | **−4.0** | **−4.3** | **−8.3** |
| 深渊 | −2.3 | 0.0 | −2.3 |

**标准档那 8.3pp 大致对半**；深渊那 2.3pp **全部**来自地图本身
（群战率那 +9pp 一点没吃掉它的通关率）。

**关于工作单那条「三档波动 ≤ ±8pp」**：标准档 −8.3pp **越线了**，这是如实记账，不是漏报。
那条线是在"宽路让绕怪变容易 → 通关率上浮"这个假设下写的，实际方向**反了**
（宽路抬高群战率 → 通关率下浮）。所以对称的 ±8pp 带不是合适的验收形状：
这是一次**有意的难度上调**，该问的是"这个代价换来的东西值不值"。
**换到的东西**：窄口 19%→2%（两头堵修好）+ 群战野生率 14/14/17% → 24/25/26%。

## 五、这一轮顺带修的两条冒烟（**测试正确性**，不是放宽断言）

把默认翻成 2 之后冒烟红了 2 条。逐条查过，**两条的根因都在断言自己身上，游戏逻辑是对的**：

| 断言 | 根因 | 修法 |
| :--- | :--- | :--- |
| 精英区没怪 | **样本太薄**。精英区是抽出来的，而 4 个区里只有 3 个能分到怪（守门区固定占一个），非守门区本来就有约 40% 是空的（空房间是刻意的节奏呼吸点）。8 个种子时"至少要有一个有怪的精英区"约有 **4%** 概率翻红 | 扫 8 个种子 → **32 个**。断言本身一字不动。修完实测：**15 个精英区里 10 个有怪**（67%），与估计吻合 |
| 守门堆保费 | **拿两次不同的随机抽签在比**。`_makeEnemy` 抽签决定是哪只怪，而精英怪自己就带一份 `+eliteBonus`。实测 roadW=2 那一档 `pPlain` 恰好抽到**巨兽(kind=elite)**，两边都是 0.66 | 改成在**同一只怪**身上量两次（先普通、再盖 keep）。修完实测：`同一只怪 titan/elite 0.66 → 0.98`；`keepPay` 关掉后 `0.66 → 0.66` |

两条都属"别用随机去赌断言"那一类，与 v11.4-p 修守门堆保费时踩的是同一个坑的**第二种形态**。

## 六、门禁修复：`probe_audit` 漏带 `?ask=0`（两条 FAIL 是同一个根因）

`tools\probe_audit.html` 在 **改动前**（`git stash` 回到 HEAD `3e9783f`）就已经是
`ok=16 FAIL=2`，两条逐字相同：

```
FAIL 逐回合战斗 有 15 个键漏过了门禁：……(没进战斗)
FAIL 重开一局后没有浮层残留（跨局残留最容易被忽略）：skill-modal
```

改后（roadw=2）依然是**同样两条**，只有模糊走位的 turn 数不同（52 → 43）。

**所以它不是路宽改出来的**，而是一条**交接文档没说实话**的状态：
`v11.5-交接-新话题从这里开始.md` 的门禁表里写着 `probe_audit.html → ALL PASS`。
这是本轮从交接里查出的**第 5 处**不实（前 4 处见 `v11.5-p0p1-两张矩阵与两次证伪.md` 第七节）。

### 6.1 两条其实是**同一个根因**

```
main.js:259   askSkill: (opts.ask !== undefined) ? !!opts.ask : askOn()
main.js:241   askOn() = !/[?&]ask=0(&|$)/.test(location.search)
```

体检页的 iframe 加载的是 `../src/index.html` —— **没带 `?ask=0`**。
于是每次 `newGame()` 都弹出「开局魂技三选一」（v11.4-q 新加的），
而那个弹窗**拦住所有输入**：

| 报出来的 | 真实原因 |
| :--- | :--- |
| `逐回合战斗 … 15 个键(没进战斗)` | `enterDuel()` 要按方向键走进敌人那一格，而方向键被弹窗拦住 → 走不进去 |
| `重开一局后 … skill-modal 残留` | `restart()` 开新局同样会弹；那不是"残留"，是**新开的那一局本来就要问** |

**所以游戏没错** —— 真人从标题页开局本来就该问（这是 v11.4-q 的设计）。
错的是**自动化驱动漏带了那个开关**：交接文档原话就是
「`?ask=0`（开局不弹魂技三选一 —— **自动化驱动必须带它**）」。

### 6.2 修法与证据

1. iframe 改成 `../src/index.html?ask=0`。
2. **补一个「选魂技」状态**（与原「选秘藏」对称），把因此丢掉的那份
   "弹窗必须拦住输入"的覆盖补回来 —— 不然这次修复会让一条断言失去对象。

结果：**`AUDITDONE ALL PASS`**，状态 × 键 从 11×15 涨到 **12×15 = 180 个组合**，
新增的「选魂技」也是 `ok`。冒烟 267 与三档 66.7 / 35.7 / 28.0 都**未受影响**
（改的是工具页，没碰模型）。
