## 二、三个实测发现（决定了下面的顺序）

### 发现 1：群战当前几乎没有杠杆
`tools\probe_squad.html`（新工具，深渊 n=300）：**90.7% 的仗是 1v1**，
≥3 只只有 0.6%，4 只全场只有 2 场 / 18393。
且多一只怪只多掉 1.3 点血 —— 因为敌人一轮就被打死，根本没机会出手。
→ 所以「+3.3pp 变简单」是**噪声**（n=300 敏感度 ±2pp），结论已撤回。
→ **第 3 条（房间 + 侦察）是让群战真的发生的前提**，不是可选项。

### 发现 2：玩家的雪球不止吞噬
即使把吞噬封顶到 +20，卡死局面里的面板仍是 `atkP 415~506 / defP 231~299`。
两个真正的驱动：
- `PROGRESSION.levelGain.atkP = 2`、`levelEvery = 4` → **每杀 +0.5 物攻，无上限**（700 杀 = +350）
- 高杀数时**装备**是主导（700 杀 = 100+ 次掉落）
→ 「数值高就秒杀」的根在这里；只抬普通怪 HP 而不动这条链，等于用敌人血量去追一个发散的数列。

### 发现 3：timeout 不是 AI 走位 bug，是"雪球让你死不了"（v11.4-d 已取证）

900 局里 **4 局 timeout**（原门禁是 0 局）。STALL 的 trace 形如
`13,10 → 14,10 → 15,10 → 15,10 → 14,10 → 13,10 ...`，看着像"AI 在两格之间横跳"
（v9 记过同一形态的「阈值抖动」）。

**先试的修法被证伪**：给 `_walkToward` 加**路径记忆**（缓存一条路径走完，
不每轮重算 A*）。结果 timeout 仍在、trace 形状不变 —— 假设错误，已撤回
（撤回的另一个理由：它平白移动了基线，standard 50.3 → 47.7）。

**取证探针 `tools\probe_aistuck.html`**（逐轮记录 pos / goal / ret / enemies / hp，
只打印失败局最后 60 轮）给出的真相：

```
2341 goal=enemy@33,21 ... 2371 goal=enemy@31,24  enemies=0
2373 goal=exit@35,7   ... 2382 正在往出口走，回合数到顶
```

AI 在第 4 层打了 **714 只怪** —— 潮汐会持续"涌入"新敌人（v2 的既有设计），
怪没清完它就一直打；等终于清空、转向出口时，已经撞上 2400 回合上限。
而它 `hp=3168`（满血）、`defP 283`：**它死不了，所以没有任何理由离开。**

→ 4 局 timeout 是**发现 2（雪球）的又一个症状**，与"1v1 平均要打 957 点伤害
才杀得掉一只怪"同一个根。**不要在这里单独打 AI 补丁** ——
v10.5 的教训是"兜底自己成了最大的 bug"，盲修行为只会换个形态复发。

## 三、建议顺序（依赖关系写清楚了）

```
① 压玩家的成长链（等级 + 装备 + 已封顶的吞噬）──▶ 让"秒杀"消失、战斗自然变长
                                        │      └─▶ 同时验证 timeout 门禁是否自然恢复
② 普通怪 HP/atk 曲线 + STANCE.every ──▶ A1 的达标线（单怪 ≥2 轮 / 一轮结束 ≤30%）
                                        │
③ 房间 + 侦察（关卡生成 + 敌人 AI）────▶ 让群战真的发生（目标：1v1 占比 < 60%）
                                        │
④ 群攻三形态（遗物 / 武器词条 / 魂技）─▶ 让"踩进多只"成为一种选择而不是送死
                                        │
⑤ 开局魂技三选一 ─┐
⑥ 掉落结算菜单   ─┼────────────────────▶ UI 层，可并行
⑦ 打击感 / 交互感 ─┘
```

**为什么 ④ 必须紧跟 ③**：一旦敌人活得过一轮，1v4 就是 6~10 次有意义的攻击；
没有群攻的玩家唯一正确打法变成"永远别踩进多只怪"——群战这个功能会自杀。

**为什么 ② 排在 ③ 前面**：路线图原案是"先只动普通怪 HP"。但发现 2 说玩家的
输出是按击杀数发散的，不先掐住成长链，敌人 HP 就得跟着玩家走，那不是调数是换模型。

## 四、下达标线（v11.4 全程）

| 项 | 判据 |
| :--- | :--- |
| 战斗长度 | 单怪场均轮数 ≥2.0、一轮结束占比 ≤30%；群战（≥2 只）均轮数 ≥2.5 |
| 群战发生率 | 1v1 占比从 90.7% 降到 **< 60%**（否则 ⑤ 没有对象） |
| 稳定性 | **0 局 stall / timeout**（当前不达标：4/900） |
| 通关率 | 不设硬上下限，但任一一档偏移 > 20pp 时先停下查是不是混进了别的 bug |
| 冒烟 | 全过，每件新机制都要有断言盯着 |
| 对照 | 每个新机制带开关（`&squad=` 已是范例），要有干净对照组 |
