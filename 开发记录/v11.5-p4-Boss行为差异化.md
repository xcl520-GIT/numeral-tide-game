# v11.5 P4 —— Boss 行为差异化（三个 Boss 各一条）

> 轮次：v11.5 · P4（P0/P1/P2 之后的第四件事）
> 结论一句话：**三个 Boss 各拿到了一条只在它身上成立的规则，开关默认关**；
> 打开它对通关率无可测影响（三档全在噪声带内、方向不一致）；
> 过程中逮到并修掉两个**自己新引入**的机制缺陷（隔着半张图推人 / 推进被完全抵消的死循环），
> 还剩 1 例异常终止，定位到**无头 AI 的既有盲点**，如实记账、本轮不修。

---

## 一、这一轮到底改了什么

工作单 v1#7 的原话是「boss 除了有名称和比较大外跟小怪没啥区别」。
P4 做的就是给每只 Boss 一条**只属于它的规则**，而且三条都挂在**现成的机制**上，
不新写系统 —— 新系统要付的代价（平衡、演出、教学）这里一点都付不起。

| Boss | 行为标签 | 规则 | 复用的现成路径 |
|---|---|---|---|
| 潮汐之主 | `tide` | 它在场时潮汐节拍**缩短一档**（16/12/8 → 12/8/4，下限 2）；它一死立刻回落 | `_tideTick` / `_tideAdvance`（节拍本身） |
| 骨潮督军 | `summon` | 每 4 回合孵 1 只幼体；**杀掉本体即停** | 孢子母那条孵化路径（同一份代码，只加一道闸） |
| 渊喉 | `roar` | 每 3 回合吼一次，沿主轴把玩家推开 1~2 格；**不造成伤害** | 裂地斩击退的两条纪律（只走主轴 / 推不动就停） |

三条的选法不是"哪个好做"，是**从它们自己的台词里读出来的**：

- 潮汐之主：`note: '本层的潮水由它驱动。它一死，水位就会退。'`
  —— 这句话在此之前一个字都没实现。现在它**精确成立**：它活着节拍快一档，死了回落。
- 骨潮督军：`note: '它把死在潮水里的东西都叫了起来。'`
  —— 同样是空话。现在它每 4 回合真的在叫东西起来，而且**杀掉它就叫不动了**。
- 渊喉：`note: '它吃东西的时候，整层地板都在动。'`
  —— 做成"地板把你推开"，而不是又一个伤害来源。它是**空间惩罚**。

### 一个刻意的设计决定：渊喉的吼不掉血

这一轮最容易顺手写错的东西就是「Boss 技能 = 打你一下更疼」。
那样做出来的三只 Boss 在玩家侧是同一只（都是"血掉得更快"），
而"它吃东西时地板在动"这句话想说的明明是**站位也会被改**。
所以吼只推人、不掉血 —— 它是裂地斩击退的**反面**（那个推的是敌人）。

## 二、开关：两层，各有各的活

```
?bossfx=1                     总开关（默认 0 = 旧行为）
模板上的 bossBehavior: 'tide'  逐只开关（模板上不写 = 这只 Boss 只有数值差别）
```

为什么是两层，而不是一个：

- **总开关**负责**对照实验**。"这一条值多少"只能靠 A/B 回答，
  需要一次能把三条一起关掉的把手。
- **模板字段**负责**逐只回滚**。三条里有一条不合适时，
  不该被迫把另外两条也关掉（那会让"到底哪条有问题"重新变成一个谜）。
- 更实际的理由：`bossBehavior` 放在数据表里，改它应该像改血线一样轻。
  它不是"规则"，是**这两只怪的设定**。

`static simulate` 已转发 `bossFx`，`tools/sim.html` 有抬头行与逐档计数行。

## 三、验收

### 3.1 关 = 旧行为（逐位相同）

`tools/sim.html?n=300&diff=all&cls=0`（默认 `bossfx=0`）：

| 档 | 通关率 | 三条行为的计数 |
|---|---|---|
| 休闲 | 66.7% | 0 / 0 / 0 |
| 标准 | 35.7% | 0 / 0 / 0 |
| 深渊 | 28.0% | 0 / 0 / 0 |

**与 P2 基线 66.7 / 35.7 / 28.0 逐位相同**，三条计数全是 0。
这里吃了一刀返工：计数第一版写在 `_tideAdvance()` 里无条件 `++`，
于是**关着开关也报 5071**。那是个读数噪声 —— 可读计数必须是
**能对着开关读**的数，否则 A/B 摆在一起会被读成"关着也发生了一万次"。
改成只数"被潮汐之主加速过"的那几次。

### 3.2 冒烟：**267 → 273**

新增第 52 节六条真链路断言（不是"读代码推的"，每条都真的把开关关掉/打开跑一遍）：

```
ok  P4 开关：关着时潮汐节拍 = 难度表原值 12、督军一只不孵（关 = 旧行为）
ok  P4 潮汐之主：在场时节拍 12 → 8，一死立刻回落 12；计数只在它活着时增长（0 → 1 ↛ 1）
ok  P4 骨潮督军：回合 4 孵出幼体「幼体」；杀掉本体后下一轮不再孵（1 → 1）
ok  P4 渊喉：回合 3 触发吼 → 沿主轴推开 2 格（19 → 21），血量一点没动
ok  P4 渊喉：玩家在感知半径之外（19 格 > alertR）时一声不吼、人不动
ok  P4 渊喉：闩生效 —— 离它 3 格时只推得动一次（计数停在 1），回到 2 格内立刻恢复（1 → 2）
```

后两条钉的都是**本轮自己踩出来的坑**（见第五节）。

### 3.3 打开开关值多少：**没有可测的影响**

`bossfx=1`，同一命令：

| 档 | 关 | 开 | 差 |
|---|---|---|---|
| 休闲 | 66.7% | 65.7% | −1.0pp |
| 标准 | 35.7% | 36.3% | +0.6pp |
| 深渊 | 28.0% | 28.0% | 0.0pp |

三个数都在噪声带内，**方向还不一致**（两个下、一个上）。
结论：P4 改的是**行为与体验**，不是数值平衡。这是它该有的样子 ——
它的目的是让三只 Boss 打起来不一样，不是让通关率动一动。

> **顺带修正一个坏习惯**：交接一直写「n=300 噪声带 ±2pp」。
> 这次拿 n=900 的同一组种子一比（标准档 39.2% vs 35.7%），
> 按二项分布算，n=300 在 p≈0.36 处的标准差其实是 **2.8pp**。
> 以后 n=300 只当**趋势线**用，要判 ±2pp 以内的差异必须上 n≥900。

### 3.4 Boss 均轮数：工作单那条验收线作废

工作单写的是「probe_fightlen Boss 均轮数 2.34 → ≥4」。
实测（`tools/probe_fightlen.html`，n=36 场 Boss 战）：**已经是 4.36，最长 14 轮，一轮结束占比 6%**。

两个问题：

1. **数本身是旧数**。2.34 是 A1 时代的读数。
2. **更根本的是它量不到 P4**。三条行为全发生在地图层
   （节拍 / 孵化 / 推人），而一场对决是自成体系的结算 ——
   它们**结构上不可能**改变"一场仗打几轮"。

所以这条验收线**撤掉**，不当判据，也不事后改成别的数来假装达标。
Boss 战的**体验**由"三条行为各自有非零计数"来证（见 3.5）。

### 3.5 三条行为的可读计数（n=900，P4 全开）

| 休闲 | 1706 | 592 只 | 397 次 |
| 标准 | 1346 | 331 只 | 252 次 |
| 深渊 | 1959 | 209 只 | 200 次 |

关着开关时这三个数**全是 0**。

### 3.6 群战率复核（督军召唤会不会把它稀释掉）

| 档 | 野生（达标线看这一列） | 召唤物 |

| 休闲 | 24% → 24% | 29% → 31% |
| 标准 | 25% → 25% | 31% → 32% |
| 深渊 | 26% → 26% | 34% → 35% |

**野生一列一动不动**（它才是判据）。召唤物那一列只动了 1~2pp ——

本身撑不起稀释。**"督军召唤会稀释群战率"这个担心实测不成立。**

## 四、归因实验：异常终止是从哪一条来的

`bossfx=1` 第一版跑出 **2 例异常终止**（1 timeout + 1 stall），而 `bossfx=0` 是 0。
1/900 这个量级说不清到底是不是噪声，所以**不能靠"看着像"下判断** ——
写了一条归因探针 `tools/probe_bossfx_iso.html`：加载同一份 `data.js`，
**在内存里**把模板上的 `bossBehavior` 逐条摘掉，四组跑的是同一份 `core.js`，
唯一差别只有"哪条还挂着"。

`n=900 × 3 档 = 2700 局/组`：

| 组 | 休闲 | 标准 | 深渊 | 异常终止 |
|---|---|---|---|---|
| `none`（对照：总开关开、模板无行为） | 67.8 | 39.2 | 26.1 | 0 |
| `tide` | 67.8 | 39.1 | 26.1 | 0 |
| `summon` | 67.7 | 39.3 | 26.1 | 0 |
| `roar`（闩之前） | 67.1 | 39.4 | 26.0 | **6** |
| `roar`（闩之后） | 67.3 | 39.6 | 26.0 | **1** |
| `all`（闩之后） | 67.2 | 39.6 | 26.0 | **1** |

**归因是决定性的**：6 例全部来自渊喉的吼，`tide` 与 `summon` 各 0/2700。

顺带得到一个干净的反直觉结论：**涨潮加速一档对通关率没有影响**
（67.8 / 39.1 / 26.1 对 67.8 / 39.2 / 26.1，1706 次加速节拍）。
"潮水更快 = 更难"在数据上不成立 —— 值得单独记一笔。

## 五、过程中逮到的两个机制缺陷（都是本轮自己引入的）

### 缺陷 A：隔着半张图推人

第一版 `_bossRoar` 只判 `turn % 3 === 0`，**完全不看玩家在哪**。
2700 局里渊喉吼了 **2921 次**（≈ 每局 9.7 次，n=300 口径下），
意味着玩家可能隔着一整张图被推来推去：看不见谁在吼、也不在它的区域里。
那种位移在玩家侧读起来就是 **bug**，而它在数据上只表现为"通关率低了 1.x pp"。

**修法**：加一道闸 —— 玩家在 `D.PACK.alertR`（8）之内才吼。
半径复用现成的常量，理由和 `_waitAlert` 里那句注释一模一样：
全游戏只该有**一个**"它察觉得到你"的距离；另发明一个，规则就会和画面慢慢漂开。

**验证**：冒烟第 52 节 ⑤（定点复现"离 19 格时一声不吼"）+ 计数从 2921 掉到 983。

### 缺陷 B：吼可以把玩家的推进**完全抵消**（死循环）

加完闸之后还剩 4 例 timeout，trace 是这样一个**周期正好等于吼周期(3)** 的纯循环：

```
5:32,13  5:32,10  5:32,10#  5:32,10#  …（40 个 #）
```

`bossAlive=true`、`nearestEnemyDist=3~4`、`hpPct=100`、`kills` 攒到几百。
读法是：**每一次吼都把玩家 3 回合的推进原样吐回去**，
而本体因为地形过不去、也追不上 —— 两个人对耗到回合上限。

这不是"难"，这是**永远走不到它面前**。

**修法：闩（latch）**。吼成功推动过之后，直到玩家**重新逼到近身（≤2 格）**才允许再吼。

- 病态几何（玩家卡在 3~4 格）：吼响一次就停 → 玩家把绕路的账走完 → 自然解开。
- 正常几何（贴脸缠斗）：玩家在 2 格内，闩每回合都被解除 → 仍然是"每 3 回合吼一次"，
  **原设计的节奏一个字没改**。

所以这道闩挡住的**恰好只有**那个病态循环，不误伤设计意图。
计数从 1572/1241/937 掉到 397/252/200（"一次逼近一声吼"），异常终止 6 → 1。

**验证**：冒烟第 52 节 ⑥（离 3 格时只推得动一次、回到 2 格内立刻恢复）。

> 这两条的教训是同一件事：**新机制的失效方式往往不是"不生效"，而是"生效得太满"**。
> 两个缺陷都不报错、不崩、三档也在噪声带里 —— 只能靠**给机制专门造一个量具**（隔离探针）看出来。

## 六、残留的 1 例：定位到**无头 AI 的既有盲点**，与 P4 无关，本轮不修

现场：`pos == exit`（32,10）、`bossAlive=true`、`nearestEnemyDist=8`、
`standingOn=7`（门格）、40 个回合的 trace 全是 `32,10#`（`#` = `_autoStep()` 返回 false）。

**机制**（读 `_autoStep`，并由定点探针 `tools/probe_ai_exit.html` 按出来）：

```js
if (!g && this.layerKills < D.PROGRESSION.leaveLayerAfterKills) { 找最近的敌人 }
if (!g) g = { type: 'exit', ... };            // 本层刷够怪 → 直接奔门
...
if (g.x === this.px && g.y === this.py) { this.aiGoal = null; return false; }   // 站在目标格上
...
for (const e of this.enemies) { if (曼哈顿距离 === 1) { 打 } }   // 贴脸兜底（只认距离 1）
return false;
```

于是「**刷够怪 → 直奔门 → 站到门上 → 门因为本体还活着而不开**」
= `_autoStep()` 永远返回 false → `playHeadless` 记成 stall。
现场 `nearestEnemyDist=8`，贴脸兜底也不触发，正好走到底。

**决定性证据：这条路径在 P4 全关的情况下同样存在。**
定点探针不传 `bossFx`（走默认关），把 AI 直接放到那个状态上按：
「刷够了 + 站在门上 + 本体活着」→ **12/20 局无动作**；
「新层 + 站在门上 + 本体活着」→ 20/20 都有动作（去打架）。

所以：**它是无头 AI 自己的盲点；P4 的吼只是把玩家（更快地）送到了门上，提高了撞见率。**

**本轮不修**，理由是硬的：修法要动 `_autoStep`，而 `_autoStep` 直接决定三档基线 ——
一改，66.7 / 35.7 / 28.0 立刻不可比，本轮所有对照实验的标尺同时作废。
它属于"AI 自己的一件事"，下一轮单独做、单独重标基线。
