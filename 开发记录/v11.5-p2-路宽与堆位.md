# v11.5 · P2 空间改造轮：路宽 与 堆位

> 2026-09-24。承接 `v11.4-n-群战站位三次证伪.md`（那篇的末尾把"关卡布局"留成了
> 唯一没试过的方向）与 `v11.5-工作单建议.md` 的 P2。
> 本轮两个改动各带一个独立开关：`?roadw=1|2`、`?packanchor=0|1`。
> 所有命令都在 `数值潮汐\` 这一层跑；平衡口径一律 `n=300&diff=all&cls=0`。

---

## 〇、结论先说

1. **路宽 2 是三轮以来第一个真正把群战率拉动的杠杆。**
   窄口占比 **19% → 2%**（两头堵的结构成因基本消失），
   群战野生率 **14/14/17% → 24/25/26%**（+10pp，远超 ±2pp 噪声带）。
   交接里那句"路宽 2 是群战唯一还没验过的几何前提"，验出来是对的。
2. **代价**：三档通关率 **−3.0 / −8.3 / −2.3pp**。标准档**刚好越过**工作单的 ±8pp 线。
   归因显示掉幅**大致对半分**：一半来自"走廊变宽"本身，一半来自群战率那 +10pp。
3. **堆贴门位无效 —— 这是对"队列是内在的"的第四次确认。**
   群战野生率 **14/14/17% → 14/14/17%**，一动不动（连样本量都没怎么变）。
   它唯一的效果是把每局回合数往下压（玩家更早撞上堆），**接触瞬间还是排头单挑**。
4. 最有价值的一条：**数据第一次把"窄口/两头堵"和"群战率"这两件事彻底分开了**
   —— 同一个回合里，一个开关动其中一个、另一个开关一动不动。

## 一、预登记量具与基线（跑之前先定死）

| 量具 | 来源 | 基线值 |
| :--- | :--- | :--- |
| **窄口占比**（区域边界格中"可走正交邻居数 ≤2"的比例） | `tools\packcheck.html` ② | **19%**（225/1215，三档一致） |
| 区域边界格总数 | 同上 | 1215 |
| 敌人近邻（每只怪"距离≤2 的同伴数"均值） | 同上 ① | 2.68 / 3.05 / 2.78 |
| **群战野生率** | `sim.html` 常驻行 | 14 / 14 / 17% |
| 三档通关率 | `sim.html?n=300&diff=all&cls=0` | 69.7 / 44.0 / 30.3 |
| 冒烟 | `tools\smoke.html` | 267 项 ALL PASS |

`packcheck.html` 的注释里本来就写着这件事的判据，这里直接沿用、不自造：

> ② 区域边界上的"口子"有多宽？…… 2×2 队形穿 1 格宽的走廊时会被迫拉成一列，
> 形状恰好在最需要之前被毁掉。如果边界大多数是窄口，那么"再加分格/再加半径"
> 都是白花力气，**该动的是关卡生成**（把区域之间的口子凿宽），而不是 AI。

**判定规则（跑之前定死）**：
- `roadw=1` / `packanchor=0`（默认）→ 三档 **必须逐位相同**（纯结构开关，默认旧行为）
- 冒烟 267 必须全过（重点：地图连通性 + 相机不变量）
- `roadw=2` → 窄口占比显著下降；三档波动 ≤ ±8pp
- `packanchor=1` → 看群战野生率（⚠️ A-lite 已证伪过同一机制，不涨是**确认**而非意外）
- **两个改动分开报**（交接明文：群战率与两头堵是两件独立的事，别互相背锅）

## 二、P2-a · 路宽 1 → 2（`?roadw=1|2`）

**做法**：`carveH` / `carveV` 参数化，横走廊多挖一行（+y）、竖走廊多挖一列（+x）。
`roadW=1` 时内层循环只跑 `d=0` 一次 —— 与原式**逐字等价**。
L 型拐角与两条走廊的交汇自然变成 2×2，所以**不需要**给"路口"单开特例
（工作单原本设想的"交汇处扩 3×3"被这一步自动覆盖了）。

### 2.1 结构（`packcheck.html`，n=30，standard）

| | roadw=1 | roadw=2 |
| :--- | ---: | ---: |
| **窄口占比（邻居数 ≤2）** | **19%** (225/1215) | **2%** (35/1625) |
| 邻居分布 2 / 3 / 4 | 19% / 29% / 53% | 2% / 43% / 55% |
| 边界格总数 | 1215 | 1625（+34%） |
| 敌人近邻平均 | 3.05 | 2.98（堆形没被破坏） |

### 2.2 平衡（`sim.html?n=300&diff=all&cls=0`）

| | 休闲 | 标准 | 深渊 |
| :--- | ---: | ---: | ---: |
| roadw=1（旧） | 69.7 | 44.0 | 30.3 |
| **roadw=2** | **66.7** | **35.7** | **28.0** |
| **Δ** | **−3.0** | **−8.3** | **−2.3** |

**群战野生率 14/14/17% → 24/25/26%**（召唤物 20/22/26% → 29/31/34%）。

配套读数：

| | 休闲 | 标准 | 深渊 |
| :--- | ---: | ---: | ---: |
| 回合 | 299.5 → 278.7 | 271.3 → 230.6 | 253.4 → 226.6 |
| 一轮结束 | 25.4% → 23.2% | 26.1% → 25.1% | 39.9% → 40.0% |
| 承伤/局 | 518.7 → 540.6 | 546.6 → 503.3 | 589.6 → 539.5 |
| 战斗轮/场 | 2.53 → 2.78 | 2.40 → 2.62 | 2.00 → 2.12 |
| 第 1 层死亡 | 22 → 32 | 111 → 135 | 189 → 202 |

### 2.3 归因：这 −8.3pp 是谁的账

跑了一次 `roadw=2&squad=0`（关掉群战，只留"走廊变宽"这一个变量）：

| 标准档 | 通关率 | 拆出来的那一份 |
| :--- | ---: | :--- |
| roadw=1（基线） | 44.0 | — |
| roadw=2 **且 squad=0** | 40.0 | **纯地图效应 −4.0** |
| roadw=2 **且 squad=1** | 35.7 | **群战率那一份 −4.3** |

三档都做同样的拆分：

| | 纯地图效应 | 群战率那一份 | 合计 |
| :--- | ---: | ---: | ---: |
| 休闲 | +0.3 | −3.3 | −3.0 |
| 标准 | −4.0 | −4.3 | −8.3 |
| 深渊 | −2.3 | 0.0 | −2.3 |

**读法**：标准档那 8.3pp **大致对半**——一半是走廊变宽本身（承伤 546.6 → 598.5，
玩家在开阔地上更容易被多只怪同时够到），一半是群战率涨了 10pp 的直接代价。
深渊那 2.3pp **全部**来自地图本身，群战率那 +9pp 一点没吃掉它的通关率
（深渊玩家本来就活在"每场都在打"的强度里）。

## 三、P2-b · 堆贴门位（`?packanchor=0|1`）

**做法**：把 A-lite 的 `anchorNearExit`（只有出口所在区用）泛化成 `anchorNearDoor`
——本区的一个**门位**旁边，即玩家进这个区唯一必须穿过的地方。
门位取自现成的 `_regionDoors()`（v11.4-j 就已经在跑的那套），不新造真源。
从门位往**区内部**退 1~3 格（门那一格自己贴着走廊，堆摆上去会顺走廊摊成一列，
而"一列"正是要被消除的形状）。**第 1 层不参与**（教学层，v11.0 定的原则）。

### 3.1 结果：群战率一动不动

| | 休闲 | 标准 | 深渊 |
| :--- | ---: | ---: | ---: |
| 通关率 · 基线 → packanchor=1 | 69.7 → 68.0 | 44.0 → 44.0 | 30.3 → 29.7 |
| **群战野生率** | **14% → 14%** | **14% → 14%** | **17% → 17%** |
| 野生样本量 n | 5214 → 5204 | 5589 → 5576 | 7592 → 7542 |
| 回合 | 299.5 → 283.5 | 271.3 → 249.3 | 253.4 → 232.2 |

**群战率的三个数字一个都没动，样本量也几乎没动。** 通关率在 ±2pp 内。

叠加在路宽 2 上（`roadw=2&packanchor=1`）也一样：群战野生率仍是 **24/25/26%**，
只在通关率上又压了一点（66.7 → 63.0 / 35.7 → 35.0 / 28.0 → 26.7）。

### 3.2 这是第几次确认

| 次序 | 改动 | 群战率 |
| :--- | :--- | :--- |
| 第 1 次（v11.4-n） | 行军阶段直取玩家 | 19% → 13% |
| 第 2 次（v11.4-n） | 整堆同时醒 | 19% → 19% |
| 第 3 次（v11.4-n） | 惊动房间加速 2× | 19% → 16% |
| 第 4 次（v11.4-p, A-lite） | **出口所在区**的堆贴出口 | 14~17% → 14~17% |
| **第 5 次（本轮 P2-b）** | **每一个区**的堆贴门位 | **14/14/17% → 14/14/17%** |

四次方向一致：**"把堆放到玩家必须走过的地方"这件事，对群战率没有作用。**
v11.4-n 的解释在这里依然成立，而且更硬了 ——
玩家 1 格/回合、敌人 ≤1 格/回合，**他永远是主动方**：他撞上谁就打谁。
从同一侧来的第二只，几何上只能落在排头身后，而"玩家四邻"里朝向来路的那一格**只有一个**。
**换遭遇位置不改变遭遇的形状**，能改变形状的只有**空间本身有多宽** —— 那正是 P2-a 干的。

**建议：`packanchor` 保持默认 0，不进主线。** 它把同一件事做了四次，四次不动；
它唯一可测的效果是把回合数往下压（玩家更早撞上堆），而那没有服务对象。

## 四、这一轮最有价值的一条：两件事被分开了

同一个回合、同一张表：

| 开关 | 窄口占比 | 群战野生率 |
| :--- | ---: | :--- |
| 基线 | 19% | 14 / 14 / 17% |
| `packanchor=1` | 19%（不动） | 14 / 14 / 17%（不动） |
| `roadw=2` | **2%** | **24 / 25 / 26%** |

交接里反复叮嘱的一句话——**「群战 ≥40%」和「两头堵」是两个独立验收，别让它们互相背锅**
——现在第一次有了数据支撑：**它们确实可以分开动，而且只有一个开关落在它们身上。**

顺带把达标线对齐一下：交接已把群战达标线改写为「野生率 + 结构 1/层」。
- **野生率：24/25/26% ≫ 12%，达标。**
- **结构 1/层**：A-lite 的守门堆仍在（本轮没动它），冒烟第 49 节守着。
- 工作单里那个旧线「≥40%」**仍然没到**，但这是三轮以来这个数字**第一次真的动了**
  （14 → 25，翻了近一倍）。

## 五、决策点（本轮不做，等拍板）

**唯一的问题：`roadw=2` 值不值那 −8.3pp（标准档）。**

先说清楚那条线的来历：工作单的「通关率三档波动 ≤ ±8pp」是在一个**假设**下写的 ——
"加宽让绕怪变容易，通关率可能上浮"。实际方向**反了**：宽路把群战率抬了 10pp，
通关率因此下浮。所以 ±8pp 这个**对称带**不是合适的验收形状：
这是一次**有意的、有方向的**改动，该问的是"这个代价换来的东西值不值"，
不是"有没有出带"。

三个候选（按代价从小到大）：

| 候选 | 做法 | 代价 | 预期 |
| :--- | :--- | :--- | :--- |
| **a · 只加宽"口子"** | 只把**区域边界那一批格**加宽，走廊其余部分仍 1 格 | 小 | 精确打击两头堵，不把整张地图的战场一起放大 —— 有望保住群战率的一部分收益、同时把"纯地图效应 −4.0pp"压回去 |
| **b · 接受并重标定** | 认下 −8.3pp，把三档基线整体重跑、写一份新的平衡基线档 | 中（基线整体重排） | 最省事，但等于把标准档的通关率永久从 44% 降到 36% |
| **c · 回调堆位/敌人数补偿** | 工作单原话："若通关率上浮过多，回调堆位而不是回退路宽" | 中 | 但本轮数据说方向反了 —— 该回调的不是堆位（它不动群战率），而是敌人数或敌人强度 |

**我的建议**：先试 **a**。理由是它正好切在归因表指出的那一半账上 ——
"纯地图效应 −4.0pp"来自走廊整体变宽带来的开阔战场，
而"两头堵"只跟**边界那 1215 个格**有关。这两个量是可以分开动的。

**第二个待拍板**：`packanchor` 建议永久默认关（理由见 3.2）。
