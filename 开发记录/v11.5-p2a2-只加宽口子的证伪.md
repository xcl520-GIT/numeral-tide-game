# v11.5 · P2-a′ 候选 a 的证伪：把"口子"加宽一层，得到的是壁龛不是通道

> 2026-09-24。承接 `v11.5-p2-路宽与堆位.md` 第五节的决策点 ——
> 那里给了三个候选，我建议先试 **a「只加宽区域边界那一批格（口子），走廊其余仍 1 格」**。
> 本文是它的实测结果：**候选 a 不成立**，而且原因不是"加宽得不够"。

---

## 一、结论先说

1. **候选 a 是一个空操作。** 窄口占比 **19% → 18%**（225/1215 → 280/1555），
   群战野生率 **14/14/17% → 15/15/18%**（在 ±2pp 带内），三档通关率 **0.0 / +0.7 / −3.0pp**。
   它既没修好两头堵，也没换来群战率。
2. **原因不是"加宽得不够"，是"宽度不能局部补"。**
   把一条 1 格宽走廊里的**若干格**加宽一格，得到的是**壁龛**（1 格厚的凹槽），
   不是**通道** —— 壁龛在它的两端自己就构成了新的窄口，
   所以窄口占比这个数几乎不动。
3. **更要紧的一条：候选 a 与候选 b（整体加宽）不是两条路。**
   区域边界不是地图上的"几个口子"，而是一条**沿走廊连续延伸的带**
   （实测把它整体加宽之后，边界格从 1215 涨到 1555 —— 新加的格**自己又成了边界格**，
   这说明走廊的大部分格子本来就是边界格）。所以"只加宽边界"在覆盖面上
   本来就接近"全部加宽"，只是每一处都只加宽了 1 格厚。

**于是决策点收敛成两条**（不是三条）：接受 `roadw=2` 及其代价，或者不动路宽、换别的杠杆补偿。
见第四节。

## 二、实测数据

### 2.1 结构（`packcheck.html`，n=30，standard）

| | 基线 roadw=1 | **roadw=mouth** | roadw=2（对照） |
| :--- | ---: | ---: | ---: |
| **窄口占比（邻居数 ≤2）** | 19% (225/1215) | **18% (280/1555)** | 2% (35/1625) |
| 邻居分布 2 / 3 / 4 | 19% / 29% / 53% | 18% / 27% / 55% | 2% / 43% / 55% |

**边界格确实变多了（+28%），但"窄口"的比例只从 19% 掉到 18%。**
也就是说：新加出来的那些可走格，自己又变成了窄口。

## 三、为什么会这样（这一节是本文真正的产出）

### 3.1 壁龛 ≠ 通道

一条横走廊（1 格高）里，格子 `(x, y)` 的可走邻居只有左右两个 → 通行宽度 2。
把它在 `(x, y+1)` 处加宽一格之后：

```
加宽前          加宽后
■■■■■■        ■■■■■■
··●··●··   →   ··●··●··
■■■■■■        ·■·····■      ← 新加的格在两端就是新的窄口
                 ↑ 新格
```

新格 `(x, y+1)` 的可走邻居只有 `(x, y)` —— **通行宽度 1**，
而且它自己也常常是"区域边界格"（它跟 `(x,y)` 同一区、跟隔壁那格不同区）。
**一加一减，窄口占比几乎不变。**

要得到"能并排站两只"的**通道**，必须**连续**加宽一段（≥2 格长），
而"连续一段"这件事一旦开始做，由于 3.2，覆盖面和整体加宽是同一个量级 ——
**中间没有省力的档位。**

### 3.2 区域边界是一条带，不是几个口子

这是候选 a 的立意本身错的地方。我当时的假设是"两头堵只跟边界那 1215 个格有关"，
隐含前提是"边界 = 少数几个窄口"。

实测把这个前提否掉了：**把边界格各加宽一格之后，边界格总数从 1215 涨到 1555。**
新加出来的 340 格**自己又成了边界格** —— 只有当"走廊的大部分格子本来就是边界格"
时才会这样。区域分区是对可走格做多源 BFS 得到的，
而一条走廊的两侧端点分别落在两个区里，于是**走廊本身就是那条边界带**。

所以"只加宽区域边界"在覆盖面上 ≈ "全部加宽"，差的只是每处的厚度（1 格 vs 连续）。
候选 a 不是候选 b 的轻量版，它只是候选 b 的**坏实现**。

## 四、于是决策点收敛成两条

原来给的三个候选里，**a 已经被证伪**。剩下的是真正的取舍：

| 候选 | 做法 | 代价 | 换来什么 |
| :--- | :--- | :--- | :--- |
| **甲 · 接受 roadw=2** | 认下 −3.0 / −8.3 / −2.3pp，把三档基线整体重跑、写新的平衡基线档 | 中（基线整体重排） | 窄口 19%→2%（两头堵修好）+ 群战野生率 14→25（三轮里唯一真的动过它的杠杆） |
| **乙 · 不动路宽，换别的杠杆补偿** | 放弃路宽，改回调敌人数 / 敌人强度来把标准档拉回 44% 附近 | 中 | 保住旧地图的一切可比性，但**两头堵与群战率都不动**（它们只有路宽动得了，见 P2 正文第四节） |

补一句关于**丙（回调堆位）**：它在 `v11.5-p2-路宽与堆位.md` 里已经被数据排除了
—— 堆位调动不了群战率（14/14/17% 一动不动），所以它补偿不了路宽带来的那 8.3pp 里的群战那一半。

**我的建议**：走 **甲**，但把代价如实记账 ——
标准档从 44.0% 降到 35.7% 是一次**有意的难度上调**，来源是两个可分的量
（纯地图效应 −4.0、群战率那一份 −4.3）。如果不想动难度曲线，
那就得同时回调敌人数/强度 —— 那是乙 + 一个小补偿，不是第三条路。
