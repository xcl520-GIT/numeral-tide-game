## 二、本轮（v11.8）做了什么：一条待办的改判

**起因**：工作单点名、且欠了两轮的债 ——「深渊开局死亡率过高」（P4 那半条），
以及那句「任何深渊改动跑完，先看这个分布有没有从 157 往中间挪」。
而它一路恶化：**157（v11.4-f）→ 188（v11.6）→ 200（v11.7）**。

### 结论：这条待办按原样做是错的

**「第 1 层死亡数」不是独立的病，它是深渊难度的温度计。**

| 版本 | 深渊通关率 | 第 1 层结束 |
| :--- | ---: | ---: |
| v11.4-f（`<120` 这条线就是在这时定的） | 39.7% | 157 |
| 现在 | **28%** | **200** |

两者是**同一件事的两面**（灵敏度表里每一行都同向）。想让它 <120，
唯一的路是给深渊复活 —— 而那会把通关率推到 **43.3%**（高于标准档 42.3%），
**深渊就不再是深渊**。

### 两次干净证伪（本轮最有价值的部分）

| 做法 | 第1层结束 | 通关率 | 判定 |
| :--- | ---: | ---: | :--- |
| 怪数砍半（`enemyMul` 1.85 → 1.0） | 200 → **206**（不动） | 28% → **15%（塌）** | ❌ |
| 关掉精英提前（`tierBoost` 1 → 0） | 200 → **210（更差）** | → 24.7% | ❌ |
| 潮水放慢（`tideEvery` 8 → 12） | **200（完全不动）** | 27% | ❌ |
| 战后回血 → 标准档（0.024 → 0.040） | 169 | 37.7% | ⚠ 降难度 |
| **`extraLife: 1`** | **110 ✅** | **43.3%** | ⚠ 越档 |

**同一个道理**：在 roguelike 里**敌人既是威胁、也是资源**（每 4 杀升级、每 6 杀秘藏）。
削敌人 = 削成长燃料，净效应为 0 或负。

### 真形状：「前重后空」

```
深渊结束层分布：{1:200, 2:11, 3:4, 4:1, 5:84}
                  ↑ 前两层死了 211 局      ↑ 第 3、4 层只死 5 局
```

所以"提高后半程陡度"完全无效：`enemyScale` 0.250 → 0.35（**+40%**），通关率只掉 **1pp**
——**那里没有人会死**。

**正确的表述是：难度全堆在前两层，后半程没有压力。这是曲线形状问题，不是"开局数值太大"。**

## 五、环境坑（新话题最容易在这里浪费时间）

1. **给热对象加字段 = 整局慢 3 倍。** 字段必须在 `reset()` / `_makeEnemy()` 字面量里声明；
   探针要存每局状态用 `Map`/`WeakMap`。
2. **无头 `--dump-dom` 下 `requestAnimationFrame` 不跑。**
3. **同一文件 `Get-Content` / `Select-String` / `readFile` 报的行号互不相同**
   → 一律用**文本锚点**，不要按行号改文件。
4. **PowerShell 不支持 heredoc** → 提交信息写成文件再 `-F`；Python 写成 `.py` 再跑。
5. `--virtual-time-budget` 会让 `--dump-dom` / `--screenshot` 挂死；截图不能加它。
6. 残留 msedge 占 profile → 输出 0 字节假象。**只杀带 `--headless` 且本项目 profile 的实例**；
   ⚠ 两个 `run_page.ps1` **不能并行**（后者会杀掉前者的实例）。
7. 控制台是 GBK → 用 `-out` 落文件再 `readFile` 取数，是最稳的方式。
8. ⚠ **`-url` 少了 `tools/` 这一层会 404，而 404 页面照样有 300KB 输出、照样报 `bytes=`**，
   看起来像跑完了 —— 取数后要检查内容里有没有 `file:///` 错误页。
9. **探针取"平均值"而不是"最后一局"** —— v11.8 第一发就栽了：怪数取了最后一局、
   血线只取第一只，而怪模板是随机抽的，读数不可比。
10. `grepContent` 在本项目的中文路径下不可用 → 用 `Select-String`。
11. 临时脚本放 `数值潮汐\_probe\<阶段>\`（已 gitignore），不要倒在工作区根目录。
