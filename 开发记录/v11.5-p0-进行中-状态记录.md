## 八、步二 · P1 设计（补丁已落盘，未验证）

### 8.1 为什么拆成**两个**开关

用户选的是"a 与 b 都做成开关，各跑一次对照"。但如果只有一个 `waitcost`，
那么 `waitcost=0` 那一组同时也是"AI 一次都不等"——**"机制变了"和"AI 行为变了"
会搅在一起，A/B 的差值归不了因**。所以拆成：

| 开关 | 含义 | 默认 |
| :--- | :--- | :--- |
| `?waitcost=0\|a\|b` | 代价本身。`0` = 旧行为（等待免费）／`a` = 等待额外推进一个潮汐节拍／`b` = 等待时半径内**已醒**的敌人各免费挪一步 | `0` |
| `?aiwait=0\|1` | 无头 AI 会不会"刷回合"。`0` = 旧 AI（一次都不等） | `0` |

**两个都默认旧行为 → `?n=300&diff=all&cls=0` 这条基线命令必须逐位不变。**
这同时是"插桩是惰性的"的证据（步二恢复后的第一条验证就是它）。

### 8.2 四组跑法

| 组 | 命令 | 它回答什么 |
| :--- | :--- | :--- |
| 不能刷 | `aiwait=0`（即步一那张表） | 谁强（无漏洞） |
| 会刷 · 免费 | `aiwait=1&waitcost=0` | **"免费等待"这个漏洞值多少**（与上一组之差，纯 AI 行为变量） |
| 会刷 · a | `aiwait=1&waitcost=a` | 代价 a 的效果 |
| 会刷 · b | `aiwait=1&waitcost=b` | 代价 b 的效果 |

### 8.3 实现落点

- `core.js` 构造函数：`this.waitCost` / `this.aiWait`（在构造函数读，因为 `reset()` 收不到 `opts`，
  与 `hold` / `cleaveOn` / `keepPay` / `askSkill` 同一形状）
- `core.js` `reset()`：声明 `this.aiWaitStreak = 0`（AI 连续等待计数，防死等）
- `core.js` `wait()`：`endTurn()` 之后挂代价 ——`a` 调 `_tideAdvance()`，`b` 调 `_waitAlert()`
- `core.js` `_tideTick()` 拆成 `_tideTick()` + `_tideAdvance()`：代价 a 必须和自然涨落走
  **同一份**周期代码（抄一份 = 第二个真源）。`waitCost='0'` 时逐字等价于改造前
- `core.js` `_waitAlert()`：复用 v11.4-i 的 `_stepEnemyTowardPlayer`，**不新写移动逻辑**；
  只推**已醒**且在 `D.PACK.alertR` 内的（推睡着的怪 = 惩罚探索，不是惩罚等待）
- `core.js` `_aiShouldWait(g)`：四条判据 ——① 安全（身边一格无敌人）② 残血（<55%）
  ③ 目标不远（≤4 格）④ **等真的有利**（`bestAttack` 在当前姿态 vs 翻面姿态各算一次）
- `core.js` `_autoStep()`：在"选完目标之后、执行之前"插入等待判断，走 `this.wait()`
  （**不让 AI 自己拼 `endTurn()`** —— 那会给它留一条免费后门）
- `core.js` `simulate` / `sim.html`：转发两个开关（含分职业循环）

**一个必须记住的技术点：** `_aiShouldWait` 的第 ④ 条**绝不能用 `_autoAtkType()`** ——
它带 `fumble`，会**多消耗一个随机数**。一局里的随机数**个数**一变，三档基线当场失去
可比性（这是本项目最贵的一条规矩）。所以用的是纯函数 `bestAttack`。
