## 三、P0 的起手式（我已勘查完落点，未动手）

### 先说一个会改变 P0 结论的前提（**必须先写进判定规则**）

**无头 AI 从不等待。** `playHeadless` 里 `_autoStep()` 永远返回"行动了"，每个回合都有动作，玩家侧的等待一次都不会发生。

两个直接后果：

- 你定的判定规则里「极差 ≤15pp 但**疾风的等待占比显著低** → 问题在机制不在数值」这一条，**在 P1 落地之前不可能触发** —— 四个职业的等待占比都会是 0%。P0 的等待占比列不是判别器，它是 **P1 的基线**。
- 更要紧的：**P0 量出来的是"在不能刷回合的前提下谁强"**，而真人玩家会刷（v1#5 的原话"法师远程来回刷回合就能轻松无伤"）。所以 **P0 的职业排序不能直接当"哪个职业过强"的判决** —— 排序未必迁移到真人。要拿 P0 的数据去调职业数值，得先让 AI 也能刷（即先落 P1 的 AI 等待策略）。

**建议：把 P0 的采集和 P1 的 AI 等待策略做成同一轮的两步**，先出"不能刷"的矩阵，再出"会刷"的矩阵，两张表一起看。只出第一张会得出一个可能不成立的结论。

### 计数器加在哪（精确落点）

| 加什么 | 加在哪 | 怎么保证逐位不变 |
| :--- | :--- | :--- |
| `this.waits` | `core.js` `reset()` 初始化；新增 `wait()` 方法 `{ this.waits++; this.endTurn(); }` | 纯计数，不参与任何判定 |
| 等待的入口 | `main.js` `waitTurn()` 里的 `g.endTurn()` → `g.wait()` | 行为完全等价 |
| `this.dmgTaken` | ① `_fightSettle`：用 `L.hp0 - res.aHp`（`L.hp0` 是开战时玩家血量，已有）② `enemyHit` 的 `this.hp -= dmg` ③ 踩水腐蚀的 `this.hp -= dmg` | 纯计数 |
| 聚合 | `core.js` `static simulate`：`out.waits += g.waits; out.dmgTaken += g.dmgTaken;`（记得在 `out` 初始值里加上） | — |

注意 `_afterAction()` 是"动作结束"的唯一漏斗，而**等待故意不走它**（等待不该被"免费行动"拦截）—— 这正是"等待零代价"的机制根源，P1 要动的就是这一条。

### 常驻指标行（用户提议的趋势线，钉进 `sim.html`）

```
        常驻 一轮结束 25% | 群战 野生 14% 召唤物 20% | 等待 0% | 深渊第1层死亡 189
```

- **一轮结束占比**：在已有的 `_fightSettle` 包装里顺手数（口径沿用 A1：1v1 + tier≤1 + kind normal + 野生）。判据是 `L.duel.round <= 1`。

- **等待占比**：`out.waits / out.turns`（P0 阶段会读到 0%，那是预期）。
- **深渊第 1 层死亡数**：`out.byDepth['1']`，现在 189。

## 五、这一轮踩到的坑（都是硬的，请沿用）

1. **冒烟里不能"等时间"。** headless 跑 `--virtual-time-budget`，虚拟时间**只在 JS 让出线程时**推进；`while (Date.now()-t0<ms) {}` 这种忙等会把虚拟时钟一起锁死 —— 实测整轮挂死（380s 无输出、`--dump-dom` 交 0 字节）。要验"会过期"这类时序，改用**可读状态**（v11.4-l 加了 `stopLeft()`）或**把 `performance.now` 临时拨到未来**。
2. **表现层改动必须做两层。** `main.js` 把 `duel/fight` 事件从 FX 队列里 `splice` 走交给 `UI.playBattle`，所以画布层（FX）**永远看不到战斗界面那一场**。打击感和音效都栽在这上面；音效那条是 v11.2-h 就存在、两轮都没被发现（因为代码在、注释在、语法自检绿、冒烟全绿）。
3. **断言必须能失败，而且要走真实链路。** 直接构造模型只能验规则，证明不了"界面上接上了"。第 50 节的第 ⑧ 条就是为此加的（开局 → 弹窗 → 右移 → 空格确认）。
4. **别用随机去赌断言。** 守门堆保费那条一开始杀怪比掉落件数，那是概率测试（偶尔红偶尔绿）。改成把 `rng.chance` 换成桩、只读被喂进来的概率 → 确定性。
5. **新机制必须带开关，且 `static simulate` 要转发它**，否则做不了对照实验。"代价是多少"只能靠对照回答，不能靠看代码猜。
6. **抽样绝不动 `this.rng`。** 一局里的随机数**个数**一变，三档基线当场失去可比性（"纯结构改动必须逐位相同"就是为拦住这个）。要另起一条独立随机流（v11.4-q 的 `_offerSkills` 是范例）。
7. **"要不要问玩家"这类界面决策，不能决定模型能不能动。** v11.4-q 第一版把候选挂在模型的默认路径上，冒烟 30 处 `TideMain.start()` 当场全卡（FAIL 37 条，原因一律 `pending`）。**默认值要为自动化选**，界面显式传 `askSkill: true`。
8. **改文件用 Python 锚点替换 + 命中数校验**，不符则整份不写。补丁脚本放 `数值潮汐\_probe\A1\`。
9. **控制台里中文是乱码**（`Get-Content` / `Select-String` 的输出编码）。读文档一律用 `readFile`；`Select-String` 只用来定位行号，不信它的内容。
10. **`--dump-dom` 偶尔 0 字节。** 先 kill 无头 msedge（**只杀**带 `--headless` 且 profile 是本项目的，否则会连用户自己的浏览器一起杀）、等 3 秒再跑。`tools\run_page.ps1` 已经把这条和另外两个坑封装好了 —— 用它，别手写。
11. **`n=300` 的噪声带是 ±2pp。** 小于这个数的差异不要据此调参（A-lite 的净影响 +2.7/+2.3/−0.4pp 就是这么处理的）。
