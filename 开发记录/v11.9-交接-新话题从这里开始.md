## 二、本轮（v11.9）做了什么：把难度搬到后半程

### 根因：一场"分母在涨"的追赶

| 深渊 | 玩家血 | 怪 atkP | 理论伤害 | 占玩家血 |
| :--- | ---: | ---: | ---: | ---: |
| 1 层 | 168 | **6** | 4.4 | 2.63% |
| 5 层 | **808** | **17** | 6.8 | **0.84%** |

**怪的攻击 ×2.8，玩家的血 ×4.8。** 怪的属性曲线是「静态模板 × 缩放」，
而玩家是**三重叠乘**（等级 + 装备 + 遗物）。伤害走 `rawDamage` 的
**饱和公式** `atk·K/(def+K)`，而血池是**纯收益**。

> 血量那一侧是平衡的（怪血 ×4.0 vs 玩家血 ×4.8），所以"几下一只"稳定在 2 下 ——
> **P5 的雪球结论在这里得到第二次印证**。失衡的只有伤害这一侧。

### 「提攻击」这条路被证伪

给深层加攻击二次项，第 5 层乘到 **4.15 倍**：占玩家血只从 0.1% → **0.6%**。
要到第 1 层那种压迫感得再乘 10 倍以上，而那会让第 3 层先爆掉。
**每场掉血的绝对值根本没变**（第 1 层 9.2 血/场、第 5 层 7.8 血/场），变的只是分母。

### 药方：深层的潮水（真实伤害 + 按最大生命比例）

| X（第3层起每场扣最大血%） | 通关率 | 条件概率 |
| :--- | ---: | ---: |
| 0（现状） | 28% | 5.6% |
| **0.06（采用）** | **23.3%** | **20.2%** |
| 0.09 | 18.7% | 36% |

**为什么有效**：按**最大生命的比例**扣，所以威胁**不随血池稀释**（血池翻倍，扣血也翻倍）。
**为什么不是新机制**：潮水腐蚀（踩水掉血）本来就是真实伤害。

### 验收

| 档 | 通关率 | 一轮结束 | 第1层死亡 | 结束层分布 |
| :--- | ---: | ---: | ---: | :--- |
| 休闲 | 72.7%（**逐位不变**） | 27%（**不变**） | 23（**不变**） | `{1:23, 2:38, 3:239}` |
| 标准 | 42.3%（**逐位不变**） | 29.8%（**不变**） | 117（**不变**） | `{1:117, 2:43, 3:8, 4:132}` |
| **深渊** | **23.3%**（−4.7pp） | 30.3% | **200（不变）** | `{1:200, 2:11, **3:18**, 5:71}` |

**第 1、2 层逐位不变**；第 3 层死亡 **4 → 18**；通关 **84 → 71**；
深渊 `deathBy` 里「潮水」**19 → 32**（新机制确实在生效）。
休闲/标准的 relics / lootRarity / deathBy **也逐位相同**。

## 四、硬约束（不要动）

- `rawDamage()` **一行不改** —— 它是"改动可量化"的地基
  （v11.9 也遵守了：病不在公式，在"用它去追一个线性增长的血池"）
- 纯结构改动的验收标准是**逐位相同**，不是"看起来合理"
- 每个提交单独跑冒烟 + 300×3；能逐位比对的地方就逐位比对
- 规则只有一个归属地：界面不直接改模型语义，一律走 core 的收口函数
- 面板文案必须说代码做的事，一个字都不多
- **可选字段 = 天然开关**：新机制写成"不写就是旧行为"（`speedGap` / `deepCorrupt` 都是）
- **多 return 分支的函数不要逐个补调用** —— 包一层（v11.9 的 `_fightSettle` 就是范例）
- **900 局必须 0 stall / 0 timeout**
- 难度变更要记账
- **新诊断先问两句**：①"它是不是也是资源"（v11.8 两次证伪的教训）；
  ②"是分子小了，还是分母大了"（v11.9 的教训）

## 五、环境坑（新话题最容易在这里浪费时间）

1. **给热对象加字段 = 整局慢 3 倍。** 字段必须在 `reset()` / `_makeEnemy()` 字面量里声明；
   探针要存每局状态用 `Map`/`WeakMap`。
2. **无头 `--dump-dom` 下 `requestAnimationFrame` 不跑。**
3. **同一文件 `Get-Content` / `Select-String` / `readFile` 报的行号互不相同**
   → 一律用**文本锚点**，不要按行号改文件。
4. **PowerShell 不支持 heredoc** → 提交信息写成文件再 `-F`；Python 写成 `.py` 再跑。
5. `--virtual-time-budget` 会让 `--dump-dom` / `--screenshot` 挂死；截图不能加它。
6. 残留 msedge 占 profile → 输出 0 字节假象。**只杀带 `--headless` 且本项目 profile 的实例**；
   ⚠ 两个 `run_page.ps1` **不能并行**（后者会杀掉前者的实例）。
7. 控制台是 GBK → 用 `-out` 落文件再 `readFile` 取数，是最稳的方式。
8. ⚠ **`-url` 少了 `tools/` 这一层会 404，而 404 页面照样有 300KB 输出、照样报 `bytes=`**，
   看起来像跑完了 —— 取数后要检查内容里有没有 `file:///` 错误页。
9. **探针取"平均值"而不是"最后一局"**（v11.8 栽过：怪数取最后一局、血线只取第一只，
   而怪模板是随机抽的，读数不可比）。
10. **同一个指标在不同探针里的口径要一致**（v11.9 栽过：两个探针算"占最大血"时，
    一个是"该层最大值"、一个是"该层第一次战斗时的值"，结果第 1 层报出 3.2% 和 5.5% 两个数）。
    **每个探针的聚合方式要写在输出里**，否则跨探针对不上时说不清是谁错了。
11. `grepContent` 在本项目的中文路径下不可用 → 用 `Select-String`。
12. 临时脚本放 `数值潮汐\_probe\<阶段>\`（已 gitignore）。
