> 比如法师，弓箭手，召唤师。游戏内有物抗和法抗的概念，没有做好明显的区分就很容易死掉。」

| | 结论 |
| :- | :--- |
| 落地 | ✅ 两只行为差异化的普通怪（弓手 / 术士），远程 = 模板上一个可选字段 |

## 一、为什么"种类"要落在**行为**上，而不是再来一只"血比较多的"

反馈原话的刀口是"除了血比较多就没有其他的"。所以这一轮**没有**加任何一只
"N 血 / M 攻"的新怪 —— 那正是玩家已经在抱怨的东西。加的是**行为差异**：

| | 现有的 4 只普通怪 | 新增的 2 只 |
| :--- | :--- | :--- |
| 打法 | 全部**贴脸**：走到你边上，然后每回合打你 | **在射程内止步开火**，不再往上贴 |
| 玩家要做的事 | 选择"打不打、先打谁" | 多一个：**顶着箭走过去，还是绕开** |

- **弓手**：射程 3，物伤，hp 72 / atkP 4 / spd 12，weight 3
- **术士**：射程 3，法伤，hp 62 / atkM 4 / spd 9，weight 2
  （只用法术打人 → 带「法术」标签，于是「高法抗」那件装备**一次挡两个**：它和幽魂）

数据上的实现只有**一个字段**：

```js
{ id: 'archer', name: '弓手', tier: 1, weight: 3, kind: 'normal', range: 3, ... }
```

`range` 不写 = 1 = 旧的贴脸怪。**可选字段 = 天然开关**，和
`speedGap` / `deepCorrupt` / `penPerDepth` 同一条规矩。

## 二、执行点：一个判据，三个调用者

远程怪的"止步开火"如果写成两处判断，就会漂移成最坏的一种：
**界面说会打、实际在逼近**（v11.5 P4 已经为同一类问题付过一次学费）。
所以只有一条判据 `_reach(e, dist)`（`core.js`），三个调用点共用：

| 调用点 | 作用 |
| :--- | :--- |
| `endTurn()` 敌人行动 | `dist <= range` 且**看得见** → 出手 |
| `_stepEnemyTowardPlayer()` | 同一个判据 → **止步**（不往上贴） |
| `_decideEnemy()`（意图预告） | 同一个判据 → 预告「打击」而不是「逼近」 |

**两条不许顺手"优化"掉的边界：**

1. **`range <= 1` 时一律不判视线。** 只有这样"不写字段 = 逐位旧行为"才成立 ——
   旧怪贴脸时从来不检查视野，现在也不能开始检查。冒烟第 57 节专门钉了这条：
   *把视野清空，贴脸的怪必须照打*。
2. **视野每回合只在 `endTurn` 末尾算一次**，所以敌人行动时读到的是
   "玩家上一步落下时"的视野。这不是缺陷，恰恰是它诚实的地方：
   意图预告也是那一刻算的，两者读同一份数据，所以
   **"预告说会打"与"真的打了"精确一致** —— 而预告的语义本来就是"若你不动"。
   多算一次视野能跟上最新位置，代价是每回合一次全图射线，不值得为一格差别付这笔账。

另外两处配套（都在数据/标签层）：

- `tagsOf()` 给 `range > 1` 的怪推上 **「远程」** 标签（行为型，只能从模板读）。
  反馈⑥抱怨的另一半正是"很少会去用鼠标显示敌人的信息"——现在不悬停也看得见。
- `canStance()` 排除远程怪：**让"读标签"和"读姿态"各管一半敌人**（同 ③ 号边界的理由）。

## 三、途中打掉的 bug：AI 与敌人互相追出来的**两格横跳**

这是这一轮最值钱的一块。900×3 门禁在第一次运行时抓到 **1 例 timeout**：

```
[abyss] outcome: {"dead":723,"win":176,"timeout":1}
STALL: depth=2 hp=416(94%) enemies=4 nearestEnemyDist=2
       trace: 2:34,18 2:33,18 2:34,18 2:33,18 …（一路跳到 2400 回合上限）
```

**定位过程**（探针 `probe_ranged_stall.html`：先扫出种子，再带插桩复现）：

1. 扫 900 局找出是第 **324** 局（`seed = 1000 + 324*7919 = 2566756`）——
   因为可以**提前退出**，只用了 9 秒，比整轮 sim 快得多。
2. 带插桩复现，打出最后 90 步决策流水。一眼看清：

```
t=2310  from 33,18 → 34,18   goal: enemy@34,14[15930 priest r1 d5 @33,14]
t=2311  from 34,18 → 33,18   goal: enemy@34,14[15930 priest r1 d5 @34,14]
t=2312  from 33,18 → 34,18   goal: enemy@34,14[15930 priest r1 d5 @33,14]
…
```

**根因：两个"朝对方走"的局部最优凑成了一对完美周期。**

- 祷者是 `kind: 'elite'` ⇒ **每回合都挪**（不受"每 2 回合一步"的限制）；
- 玩家 AI 每轮 `_walkToward(敌人当前位置)`，敌人每轮朝玩家挪；
- 这张图的地形让"第一步"随目标的**列**翻转：玩家在 33 列时朝 34 列迈，
  在 34 列时朝 33 列迈 —— 而敌人也在两列之间同步翻转；
- 结果：双方各跳各的，**距离稳定停在 5**，谁都没犯错，永远走不到一起。

`findPath` 不是嫌疑人：目标不可达时它返回 `null`，那条路早被
"记黑名单 + 清空目标"接住了。这里返回的是**真实可达的路径**，只是对方在动。

**修法**（沿用本项目对"两格横跳"的既有纪律，见 `_retreatStep` 那段注释）：

```js
// _autoStep() 开头：净位移为零的往返 = 这个目标走不通
if (this.px !== this.aiPx1 || this.py !== this.aiPy1) {
  this.aiBack = (this.aiPx2 === this.px && this.aiPy2 === this.py) ? this.aiBack + 1 : 0;
  this.aiPx2 = this.aiPx1; this.aiPy2 = this.aiPy1;
  this.aiPx1 = this.px; this.aiPy1 = this.py;
}
if (this.aiBack >= 3) {            // 连续 3 次才动手
  this.aiBack = 0;
  if (g) {
    if (g.type === 'exit') { this.wait(); return true; }   // 静态目标不该横跳；真到了就消耗一回合
    this._badGoal(g);                                      // 沿用"走不到"那条纪律
  }
  this.aiGoal = null; g = null;
}
```

三个设计要点：

1. **连续 3 次才动手**：偶尔掉头是正常的（敌人绕到了你身后，最近的路就是走回去），
   那种局面下一步就踩到新格、计数自动归零。这条"只认连续"让守卫在
   **健康局面里完全惰性** —— 它只在本来就是死局的地方改变行为。
2. **走的还是那条既有出口**（`_badGoal` 拉黑 + 清空重选），不新造机制：
   换一个目标照样能打（贴脸的兜底不看黑名单），而它只影响**这一个**目标。
3. **不加开关**：和 v11.11 修 `_autoStep` 那四处一样 —— 它是修 bug，不是旋钮。

**证据**：同一支探针重跑 → `NO HIT in 900`；完整 2700 局 → 三档 **0 stall / 0 timeout**。

⚠ 关于"这例 timeout 是不是我引入的"：往 `ENEMIES` 表里加条目会**重排整条随机流**
（见第四节），所以改动前后不是同一批世界，无法用"改前 0 例"直接判定归因。
能确定的是：这一类横跳是**本项目反复出现过**的形状（`_retreatStep` 的注释里
记着同款 trace `12,32 → 11,32 → 12,32 …`），而现在它被一条**通用**守卫补上了。

## 四、记账：一条比数字更重要的读数纪律

### 4.1 定稿对照（n=900，同一把尺子：`diff=all&cls=0`，默认开关）

| | 改动前 | 定稿 | 差 |
| :--- | ---: | ---: | ---: |
| 休闲 通关率 | 71.8% | **72.1%** | +0.3pp |
| 标准 通关率 | 42.0% | **40.9%** | −1.1pp |
| 深渊 通关率 | 19.8% | **19.6%** | −0.2pp |
| 第 1 层死亡 休闲 | 55 | 42 | −23.6% |
| 第 1 层死亡 标准 | 354 | 356 | **+0.6%** |
| 第 1 层死亡 深渊 | 541 | 536 | −0.9% |
| 一轮结束 休闲/标准/深渊 | 27.4 / 28.9 / 33.8% | 30.1 / 32.4 / 35.8% | +2.7 / +3.5 / +2.0pp |

跑前写死的判据是"通关率偏移 ≤ 4pp、第 1 层死亡偏移 ≤ 10%" ⇒ **全部通过**。

⚠ **一条要单独记账的副作用：「一轮结束」升高了 2~3.5pp。**
原因是两只新怪**脆**（hp 62 / 72，防御 3/3），于是"一场仗只打一轮"的比例上去了。
它不违反任何判据，但这条指标是 v11.5 P0 用来盯"普通怪曲线（让战斗长到 2~3 轮）"的，
所以必须留痕：**如果以后要继续抬这两只的分量，优先抬血量而不是每击** ——
抬血量能把它从"一刀一个"里拉回来，抬每击只会让"一轮结束"更难下来。

### 4.2 调参轨迹与"尺子"本身

| | 改动前 | 第一版 | 第二版 | 第三版 | 定稿 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| n=300 休闲 | 71.0% | 63.3% | 65.3% | 70.3% | 72.3% |
| n=300 标准 | 42.7% | 37.3% | 39.0% | 38.3% | 38.0% |
| n=300 深渊 | 21.7% | 19.0% | 19.7% | 20.0% | 19.3% |

第一版 → 第二版 → 第三版，**代价连砍两轮**（权重 6/5 → 4/3 → 3/2、每击 6/8 → 5/6 → 4/5），
而标准档的差值几乎不动（−5.4 → −3.7 → −4.4pp）。同一份**定稿**换 n=900 去量，只差 **−1.1pp**。

⇒ 结论（同样写进了 `data.js` 的注释）：

> **往 ENEMIES 表里加条目会重排整条随机流。** `_enemyPool` 按权重累积和抽签，
> 池子里多两项，同一个随机数就落到另一只怪身上 —— 改动前后根本不是同一批世界，
> 两边的差里混着一次完整的重新生成。
> **内容新增的难度验收，n=900 才算尺子，n=300 只够看方向。**
> 下一次别再拿 n=300 的 pp 去调代价 —— 那是在追一个样本的运气。

顺带查到、也留档的一条事实：砍权重会让池子**总权重**变小，tier2/3 精英的
**占比反而升高**（28.6% → 31.6%），所以"少放远程怪"不是一条免费的路。

定稿后两只合计约占第 1 层刷怪的 **9%**（冒烟实测 12 + 6 / 200），
`deathBy` 里已不再是主要死因（标准档 弓手 3 / 术士 3）——
它们是**过路费**而不是**行刑者**，这正是"行为新品种"该有的分量。

> 如果实际玩起来觉得太轻：**把每击 4/4 调回 5/5，然后重跑 900×3** 即可。
> 那条代价换的是"遇到一次有多疼"，不会动到机制本身。
> 反过来若觉得太烦人：优先动**权重**（它只改"多久遇到一次"），但记住 4.2 里
> "砍权重会抬高精英占比"那条事实。
