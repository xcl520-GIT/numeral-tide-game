## 二、本轮（v11.10）做了什么：三项

### 第 1 项：把「后半程压力」钉进 `sim.html` 常驻指标行

口径：**到过第 3 层的局里，有多少死在第 3、4 层**。输出末尾现在有一列
`后半程(死3-4/到过3) 35.5% (39/110)` —— **配着分子分母一起看**，
否则单看百分比分不清"压力变大"和"分母变小"。

两个口径坑（实现里都堵住了，注释写了为什么）：
① 通关局也写在 `byDepth` 里（通关时 `g.depth` = 该难度最大层），**必须先摘掉赢家** ——
   否则标准档会算出 `(8+132)/140 = 100%`；
② 分母取 `endDepth>=3` 的全部，不是"第 3 层死亡 + 赢家"（后者在第 4 层有死亡时会漏算）。

**★ 读这个数必须连着样本量**：`n=300` 时 1σ ≈ **±4.2pp**（分母只有 89 局）。
同一个基准，`n=300` 读到 20.2%、`n=900` 读到 16.6%。

### 第 2 项：深渊前两层门槛 —— **搬家**，不是降难度

先补一条结构认识：**第 1 层不吃 `enemyScale`**，它的强度旋钮只有
数量 / 精英 / 补给三个，而前两个 v11.8 已证伪（敌人既是威胁也是资源）。
⇒ **补给是第 1 层唯一还剩的杠杆**（这解释了 v11.8 那张表为什么"有效药方全在降难度"）。

转折点：v11.9 的 `deepCorrupt` 让"削前两层 + 补后半程"第一次可以**不是降难度**。

**采纳 M1**：`healAfterWin` .024→**.040**（= 标准档）+ `deepCorrupt` .06→**.105**
（n=900 判定：通关率 21.8% → 22.8%、**总死亡 704 → 695 守恒**、
第 1 层死亡 627 → 541、到达第 3 层 241 → **305（+27%）**、第 3-4 层死亡 40 → **94**）。

**复活流被否**（`extraLife 1` + 腐蚀 .135）：通关率 **35.3%** 越档、
总死亡 **194 不守恒**、单局回合翻倍 —— 那是"换游戏"，不是"搬家"。

### 第 3 项：装备堆防御那条债 —— **给防御一个对手**

5 发探针拆成三层：

① **症状不在了**：三档 max defP = 111 / 139 / **192**，够不到债里记的 231~299，900 局 0 stall。
② **防御是生存支柱**：消融（装备防御清零）掉 **8.0 / 8.3 / 7.0pp**。
   ⚠ 第一发读到"defP≥150 的 11 局全部通关"是**幸存者偏差**（通关局回合长 683，自然捡到更多装备）
   —— v11.6 栽过同一个，**分开两者的唯一办法是消融**。
③ **怪物的穿透恒为 0**：`_scaleEnemyStats` 只缩放 hp/atk/def，`penP/penM` 原值透传，
   而 ENEMIES 模板没一个写 `penP`，被兜底补成 0 —— 玩家的防御在打一场没有对手的仗。

**药方 = 穿透（不是抬攻击）**：伤害公式 `atk·K/(def+K)` 是**饱和**的，抬 atk 先杀低防玩家；
**穿透是减法**，削的是防御的绝对量 —— 它是唯一能"**对抗**防御"的手段
（`deepCorrupt` 是"绕过"）。
**它精确地打在靠防御活下来的人身上**：低防桶（200 局，全死在前两层）承伤 6.1 → 5.9 纹丝不动，
中防桶承伤 2.4 → 3.0、通关率 71.9% → 60.3%。

**落点 +8×(层-1)**（n=900）：通关率 −2.7pp、**第 1 层死亡逐位不变**、
装备防御的价值 6.9pp → **4.2pp**（仍然有用，但不再是万能）。

## 五、环境坑（新话题最容易在这里浪费时间）

1. **给热对象加字段 = 整局慢 3 倍。** 字段必须在 `reset()` / `_makeEnemy()` 字面量里声明；
   探针要存每局状态用 `Map`/`WeakMap`。
2. **无头 `--dump-dom` 下 `requestAnimationFrame` 不跑。**
3. **同一文件 `Get-Content` / `Select-String` / `readFile` 报的行号互不相同**
   → 一律用**文本锚点**，不要按行号改文件。
4. **PowerShell 不支持 heredoc** → 提交信息写成文件再 `-F`；Python 写成 `.py` 再跑。
5. `--virtual-time-budget` 会让 `--dump-dom` / `--screenshot` 挂死；截图不能加它。
6. **残留的无头实例占着 profile → 输出 0 字节假象。**
   处置顺序：只杀"带 `--headless` **且**匹配本项目 profile（`edgeprof_smoke`）"的实例 →
   删掉 `%TEMP%\edgeprof_smoke` → 重跑。
   ⚠ 两个 `run_page.ps1` **不能并行**（后者会杀掉前者的实例）。
7. 控制台是 GBK → 用 `-out` 落文件再 `readFile` 取数，是最稳的方式。
8. ⚠ **`-url` 少了 `tools/` 这一层会 404，而 404 页面照样有 300KB 输出、照样报 `bytes=`** ——
   取数后要检查内容里有没有 `file:///` 错误页。
9. **探针取"平均值"而不是"最后一局"**（v11.8 栽过：怪模板是随机抽的，读数不可比）。
10. **同一指标在不同探针里的口径要一致**（v11.9 栽过），
    **且样本量要一起读**（v11.10 栽过：n=300 的条件概率 1σ ≈ ±4.2pp）。
11. **探针里覆盖函数时，别忘了它可能有兜底分支**（v11.10 栽过：给怪"乘穿透"乘的是 0，
    三组读数逐位相同 —— 这个 bug 撞出了正确答案，但**如果不是"全不动"这种极端读数就会被漏掉**）。
12. **断言里别写死参数**（v11.10 栽过：`deepCorrupt` 一调值，冒烟第 56 节就 FAIL，
    而它报的样子和"机制坏了"一模一样）。
13. `grepContent` 在本项目的中文路径下不可用 → 用 `Select-String`。
14. 临时脚本放 `数值潮汐\_probe\<阶段>\`（已 gitignore）。**探针本身也放那里**，
    放 `tools\` 会进 git。
