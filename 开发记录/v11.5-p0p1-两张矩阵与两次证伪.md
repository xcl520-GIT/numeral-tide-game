## 〇、结论先说（三句，后面全是证据）

1. **P1 的机制与开关全部落地且验证过了**（两个开关默认关时，三档基线**逐位不变** = 69.7 / 44.0 / 30.3）。

   P0 的极差（49~64pp）既不能当"哪个职业过强"的判决，**暂时也没有第二张表能拿来把它拆开**。

## 六、本轮真正的产出：**两次证伪**

AI 等待策略连做两稿，都被数据否掉。这两条比矩阵更值钱 —— 它们说清了"等待在这个游戏里到底值多少"。

### 6.1 第一稿 · 盯"敌人姿态翻面" → 等待占比 0.0~0.1%

**原始推理**：敌人姿态每 `STANCE.every` 次行动翻一面，等到它把软的那一侧朝向我，这一轮就多打一截伤害。

**证伪的理由不是判据写错，是杠杆本身不成立**：
姿态只影响**敌人自己的防御**（`stanceDef`），而玩家 / AI **每一轮本来就能自己换一路**（v11.2-e 拆掉了自动择优）。
`bestAttack` 在两种姿态下的取值几乎一样 —— **凡是"我随时能自己拿到的东西"，都不可能靠等来赚。**

### 6.2 第二稿 · 盯"魂技冷却"（唯一随回合变好的量）→ 等待占比 0.2~1.0%

`endTurn()` 里每回合在动的量，**只有 `this.skillCd--` 是往好的方向**。
所以改成：残血 + 安全 + 目标不远 + 魂技差 1~3 回合转好 → 等。
结果仍只有 0.2~1.0% —— 窗口太窄（`skillCd` 只有 3/8~10 的时间落在 1~3，再叠残血与安全）。

### 6.3 顺带排掉的两个候选

| 候选杠杆 | 为什么不行 |
| :--- | :--- |
| **站泉水刷回血** | 这个漏洞**早就堵了**。代码注释原话：「泉水一次喝完就枯。之前做成可重复使用，结果是玩家（和模拟 AI）可以原地无限回血，血量这个稀缺资源直接失效。」 |
| **等高水位退去看/过** | 算一下就否掉：踩水腐蚀 0.6% + 水位×0.5% 最大生命/回合，穿 5 格水约 5 回合 ≈ 8% 血；而从水位 3 退到 0 要等约 20 回合。**等不如直接走。** |

### 6.4 收支表（这一节是整轮的地基）

**每等 1 回合的收支：**

| 在变好 | 在变坏 |
| :--- | :--- |
| `skillCd` −1（唯一） | 潮汐 phase +1（水位可能涨） |
| （姿态 / 泉水 / 退潮 —— 全部已证伪或早已堵住） | 敌人 `cd` +1（每 2 回合挪一步，逼近你） |
| | 自身增益剩余回合 −1 |
| | 站在水里还要吃一记腐蚀 |

**结论：`等待零代价` 是真的，`等待划算` 是假的。**
在有回合经济、且没有任何"回复型"机制的体系里，理性的 agent 不该为收益去等。
玩家说的"刷回合"更可能是**安全的回合**（不敢往前走），而不是**赚钱的回合**。

**这条推论的直接检验**：P1 上线后去问玩家"现在刷回合还舒服吗"。
**如果体感不变，说明 P1 的靶子偏了** —— 那真正该修的是 v1#4 那个痛点（"数值高就直接秒杀，所以没有过程"），
而不是等待。

## 八、建议（本轮不做，等拍板）

1. **P1 的两个做法先不要定数值、不要进主线叙事。** 它现在既没有验收数据，
   也没有已证明的服务对象 —— 「等待占比 <8%」这条线在"无约束"时就已经只有 0.2%，
   它测的不是"代价够不够重"，而是"AI 本来就不等"。
   **保持两个开关默认关**（基线因此仍然逐位可比），把"代价该多重"挂起。
2. **如果一定要给真人用**，建议开 `?waitcost=b`（累积惊动）：它惩罚的是"安全的回合"，
   语义上最贴玩家的抱怨；但**代价具体多重没有数据支撑**，属于凭判断落子，要明说。
3. **下一轮更该做的是 P2**（路宽 1→2 + 堆改必经之路）—— 它有明确的验收线（群战野生率 ≥40%）
   和明确的服务对象（v1#1 两头堵 + 群战凑不齐），比 P1 的收益可验证得多。
4. **P0 的排序仍然不能当判决**（原前提不变），而且现在多了一条：**也没有第二张表能把它拆开**。
   要拆开，得先让 AI 有"等的理由" —— 而第六节说明，在本作的回合经济下那个理由不存在。
